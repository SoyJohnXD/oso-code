# 0140 — The per-rule rationale block leaves the linter, and the ceilings it carried land here

Date: 2026-08-10
Status: accepted
Supersedes: ADR-0132 (its Part 3 exemption alone — `tests/plugin-lint.sh` no longer documents a reason above each rule and no longer claims that shape in its own header; the citation ban that decision installed, its file set, its notations and every bound Part 1 and Part 2 record stand unchanged) and ADR-0134 (its Part 3 alone, for the same clause and on the same terms; the debt class itself, its three layers and its doc-form carve-out stand unchanged)
Superseded-by: ADR-0154 — retires only this decision's scope boundary ("The purge is scoped to the two test files. A wider one over `plugin/hooks/`, `bootstrap/` and `tools/` was offered and rejected") and, with it, the consequence that a rationale block older than them stands until a sweep that names it. That sweep ran and named them; the per-rule rationale convention stays retired and the ledger of ceilings below stays where it is
Reconciled: applied — `tests/plugin-lint.sh` keeps its shebang, `set -euo pipefail` and one two-line header naming the count `check_present_tense_prose_names_the_rule_count` holds three surfaces to; 746 comment lines are gone and two written back, the purge touching no line of code and no blank beside them, and the thirty-three rules' locators, patterns, marker sets and registration order exactly what they were. `tests/hooks-test.sh` loses the 84 rationale lines the two changes named in Source added above their own new cases, plus one sentence pointing a reader at reasons that no longer exist, and keeps its `# ---` section dividers, which are that file's universal sectioning device. Every ceiling and measured near-miss those comments carried and no other artifact records is in the ledger below.
Source: the operator, on their own harness: "aplicamos una pasada de eliminacion de comentarios y demas, asi dejamos limpio todo… limpiamos todos estos comentarios inline que siguen apareciendo"; two changes (clean-bar-convergence, roadmap-auto-mode) in which 77% of the volume one slice added to executable files was rationale prose, and which together took `tests/plugin-lint.sh` from 384 comment lines over 551 of code to 746 over 816

## Decision

The per-rule rationale convention is retired. `tests/plugin-lint.sh` carries no reason above a rule, and its header no longer claims that it does.

ADR-0134 set the inline comment as a debt class with no exceptions for the code a change lands in a project, and ADR-0132 Part 3 and ADR-0134 Part 3 then claimed one file, by name, inside itself, as standing outside that class. Two changes later the harness had written 746 more comment lines into that one file under the exemption it had granted itself, and the header's claim — each rule states its own reason above it — was already false for the rule that landed without one. A bar that holds everywhere except in the file that documents the bar is not a bar, and a header that keeps claiming a convention over a file that no longer follows it is the false-claim defect these two changes exist to kill.

What replaces the convention is not a shorter comment. It is this file for the facts a maintainer cannot re-derive, the flag messages and function names for everything the code can say itself, and `tests/hooks-test.sh`'s per-rule mutation cases for what each rule actually catches.

Two boundaries hold.

**The purge is scoped to the two test files.** A wider one over `plugin/hooks/`, `bootstrap/` and `tools/` was offered and rejected: those files' bytes are published as hashes (`bootstrap/hook-hashes.txt`) and one of them is a Codex trust boundary, so an edit there costs a hash roll and a re-trust for a readability win, on files no applier reads to learn how this project writes a rule.

**No rule's behaviour moved.** Not a locator, not a pattern, not a marker set, not the registration order, not the declared count of thirty-three across its four surfaces. Proven rather than asserted: the linter was run before and after over fourteen fixture trees — one pristine and thirteen each mutated to fire a different rule, including a tree with `docs/decisions/` removed so the missing-scan-path branch runs — and every report is byte-identical, `lint: clean` and all fifty-nine violations of the worst of them included.

## The ledger of what the reasons carried

Every reason in that file was one of three things. Most were the defect the rule was built for, and the decision that installed the rule already records it — the reasons behind the citation rule are ADR-0132's, behind the wave-1 guard ADR-0126's, behind the sweep bar and the sweep memory ADR-0130's and ADR-0131's, behind the three inline-comment rules ADR-0134's, behind the five roadmap rules ADR-0135 through ADR-0139's, and behind the call-site vocabulary rule ADR-0114's, whose own "What the rule cannot check" section already states that rule's ceilings. Some were the rule's own locator or marker list, which the code states more precisely than prose can. What is left is this: the ceilings, the shapes a pattern deliberately does not catch, and the near-misses somebody measured. They are recorded here because nothing else records them.

**The file's own two conventions.**

- Pure `sed` and `grep`: no `jq` and no `git`. `tests/hooks-test.sh` runs this linter as one of its own cases and CI runs that suite in the `bash:3.2` container, which carries neither tool.
- A rule that scans a TREE keeps grep's stderr inside the value it scans (`2>&1`), the way `bootstrap/verify.sh`'s CR-byte check does. `|| true` alone reads an unreadable or missing scan path exactly like "no matches", and a rule that scanned nothing must never report clean. A vanished scan path therefore surfaces as grep's own error text among that rule's violations — misnamed, but loud and nonzero, which is the point.

**`check_call_sites_speak_their_emitters_verdict_vocabulary`.** `token_is_routed` passes `-h` to drop grep's own filename prefix from the piped line: a fixture path ending in `-fixture` carries `fix` as a plain substring, and without `-h` that path text, never the prose, is what satisfies the route-word test. Measured, and the fixtures whose paths carry it are the ones this rule's own cases copy into. Its other ceilings are ADR-0114's.

**The three delegation-payload rules** — `check_verifier_launches_name_their_payload`, `check_integrator_launches_name_their_payload`, `check_plan_delegation_payloads_name_a_specific_coordinate`.

- All three read a launch as ONE line, because the payload is what the launched agent reads in one place. A launch worded across two lines is invisible to them, and every launch site is a single line today.
- Line scope is what the verifier rule was narrowed to and why: `skills/debug/SKILL.md` names the rubric path at its APPLIER launch, so the file-scoped shape read clean over the very file whose verifier launch was starved.
- The integrator rule SEES a line only when it carries BOTH `oso-integrator` and `launch` (the second matched case-insensitively). A launch worded around only the first — `hand oso-integrator the wave…` — is invisible, and the linter goes on reporting clean over it.
- That rule requires three markers and deliberately not a fourth: the rubric is absent because the integrator writes no code and judges nothing. The bar belongs to the integration gate that follows, a separate `oso-verifier` launch the verifier rule already holds to naming `rubric.md`, and a launch line that hands the merger a rubric reads as though the merger judged the merged tree — the exact confusion a merge-only agent exists to prevent. The integrator's own contract is the one file the scan drops: it is what a launch is read against, never a launch itself.
- The coordinate rule is a POSITIVE requirement, never a ban on the retired `BASE REF` spelling — a rule that only rejected the old string would pass a launch naming no coordinate at all, which is the identical ambiguity. It exempts a `debt cleanup` or `judge findings` launch, whose kinds are self-contained by the applier's own contract and structurally carry no coordinate, and it is scoped to the `plan` skill because `/debug`'s launches legitimately say BASE REF for the single pending-tree ref that flow has ever had.

**`check_executables_carry_no_decision_citations`.** ADR-0132 records the file set, the three comment markers, the four notations, the `[ABDS]` letter bound with both measured near-misses (a markdown heading level, a two-character span inside a backticked character class), the bare-four-digit bound and the two shapes it would still flag. Three ceilings of its LOCATOR are recorded only here:

- The locator is the LINE, never the syntax tree, so a `#`-leading line inside a heredoc reads as a comment — which errs toward flagging, never toward missing one — while a string literal on a line opening with none of the markers reads as exempt whether or not it earns the exemption.
- PowerShell's `<# … #>` block is the one shape a line locator cannot reach: its interior carries no marker the block itself puts there, so a citation on a line that does not happen to open with one is out of sight and held by review, beside the provenance-string half of the exemption ADR-0132 records.
- The flag names `path:line` and none of the line's text on purpose: quoting the line would reprint the citation into this linter's own output, the one place the ban cannot reach.

**`check_present_tense_prose_names_the_rule_count`.** The header and README are read in full because they always describe THIS moment. The changelog is read at its TOP entry alone, and only for the one line shaped like a rule-count claim: every entry below it is a release already shipped, and a rule that read those would demand history be rewritten. The moment a later release's heading lands above it, that entry stops being the top one and the rule stops reaching it — frozen the same way the entry itself will be. The count includes this rule, which is the only way it can ever be right, and a count past the spelled table's end flags rather than guessing at a word.

**`check_sweep_exit_bar_is_banded_and_capped`.** Its first half reads only the `**Exit bar**` line — this repo's dense single-line style — so a statement contradicting the bar restored ELSEWHERE in either body is out of its reach. The literal carries the closing `**`, so the same label worn with a qualifier (`front-surface.md`'s `**Exit bar, read as an ADAPTER**`, a different judge's loop) is a different string and the shared vocabulary collides with nothing. Its second half's locator is a co-occurrence — a line naming `` `Debt Sweep: clean` `` with no `` `Debt Sweep: findings` `` beside it is naming the retired bar — and that is a heuristic, not a proof: a restatement worded around the tokens ("once the sweep comes back clean") still passes. The judge's own body is deliberately off that surface list, because its verdict list defines one token per line.

**`check_sweep_loop_remembers_its_dispositioned_findings`.** Each sender is located by one `re-invoke the debt-sweep judge` line, and there is exactly one such line per body today, so both markers are asked of that one value. A second re-invocation line would join it and the markers could then be met by the pair rather than by each — this shape's ceiling, and not a claim it makes for itself.

**The four roadmap phase rules** — approval, autonomy policy, chain, presence.

- Each is located by its phase's own heading, read to the next `## `, so a renumbering keeps the anchor and a deleted phase fails at it.
- The neutral body alone is scanned, and that is the ceiling of every one of them: where a host's rail asks for more than the one approval, or adds to the same policy, is that platform file's own answer, so holding those files to these markers would flag the very file that records the degradation.
- The chain rule's hook marker carries its closing paren — `state_value "$state_file" roadmap)` — or a hook renaming the key to `roadmap_slug` would satisfy a check looking for a prefix of its own new name. That rule holds the SPELLING across three files and nothing about behaviour: whether the hooks then behave is `tests/hooks-test.sh`'s, where the sweep's reach and the signal's silence are proved case by case.

**`check_roadmap_condition_never_loosens_the_operator_rule`.** Each host's always-loaded routing file carries the same absolute instruction as one of the OPERATOR's own global rules rather than as a step of this flow, so neither file is on this rule's list. Within the two texts that are, a rewording that keeps a clause in other words ("queues" for "queued") fails — which errs toward flagging rather than toward missing one.

## Context

The measurement is what settled it. Across the two changes in Source, rationale prose was 77% of the volume added to executable files in one slice, and the file claiming the exemption ended with 746 comment lines standing over 816 lines of code — 362 of those comment lines written by those two changes, against 265 lines of code. None of that prose is checked by anything: a comment is the one artifact in a source file that no test, no linter and no reader ever compares against the lines it describes, so a specification written above a rule drifts from the rule the first time the rule moves and nothing goes red. The rules' own decision files do not have that property — a decision is a dated record of what was decided, not a description of current code — and neither does a mutation case, which fails when the rule stops catching what it names.

The exemption's original argument was that a preceding block is the only place shell has to put a contract a name cannot carry. That is true of a contract; it is not true of most of what was written. The reasons that were the defect behind a rule were already in a decision file, in more detail, indexed and openable — written twice, and drifting in one of the two copies. The reasons that were the rule's locator or marker list restated what the next four lines of code already said exactly. What actually could not live in code is the ceiling: the shape a pattern deliberately does not catch, which no pattern can state about itself. That is the whole of what this file now carries, and it is one document rather than thirty-three preambles.

Retiring the convention rather than trimming it was the operator's choice between two offers. A bounded purge — keep the shape, cut the volume — leaves the exemption standing and with it the reading that made a rule's preamble the right place for prose, which is what grew 746 lines the last two times. It also leaves a header claiming a convention that one rule already broke.

## Consequences

- The exemption ADR-0132 and ADR-0134 granted one file is gone, and neither decision's substance moves: the citation ban still holds every executable here, and the debt class still holds every line of code this harness writes into a project. What is retired is the carve-out, from both ends, named in the `Supersedes:` line above.
- A ceiling is now recorded where a reader who needs it will look for one — beside the decisions that installed the rules — instead of above the function, where only a reader already editing that function ever saw it. The cost is the other direction of that trade, and it is real: a maintainer editing a locator no longer has its ceiling in front of them and has to know this file exists. The blueprint's decision index is what makes it findable, and the rules' own flag messages name the rule and the surface at the moment one fires.
- `tests/hooks-test.sh` keeps every `# ---` divider and every pre-existing comment the two changes only rewrapped. The purge was scoped to what those changes ADDED, so a rationale block older than them stands until a sweep that names it — visible, rather than silently half-done.
- The suite is the artifact that proves the rules still hold: 1394 cases, unchanged in count, over a linter whose comment volume fell from 746 lines to two. No case was added, removed or renamed by this cleanup.
- The two documents that describe the rules to a human — the header's count line and README's linter row — say what they said before. The row enumerates what the rules CHECK, never why each is decidable, so the retirement leaves it true as written.
