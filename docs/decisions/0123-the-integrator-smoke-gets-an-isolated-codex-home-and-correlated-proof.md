# 0123 — The integrator smoke gets an isolated Codex home and correlated proof

Date: 2026-08-06
Status: accepted
Amends: ADR-0100 (the outer sandbox stays `danger-full-access`, but no longer points at the operator's real `CODEX_HOME`), ADR-0102 (retires the per-run `cleanup_smoke_project_config` table removal, replaced by never writing the real file at all)
Implemented-in: bootstrap/verify-codex.sh, tests/hooks-test.sh, docs/parity-codex.md, docs/blueprint.md
Reconciled: applied — `verify-codex.sh` gains `populate_smoke_codex_home`, called from `create_integrator_fixture`; `run_integrator_fixture` launches with `CODEX_HOME="$SMOKE_CODEX_HOME"` and `--dangerously-bypass-hook-trust`; `cleanup_smoke_project_config` is deleted; `integrator_handoff_consumed` requires a completed `spawn_agent` collab tool call, a completed `oso-state handoff wait` and a completed `oso-state handoff consume` to agree on one Codex-assigned agent id, each parsed with `shlex.split(..., comments=True)`. Nine pre-existing orphan tables were removed from the operator's real `~/.codex/config.toml` after a verified backup.
Source: the operator's real `~/.codex/config.toml`, which carried nine orphan `[projects."/tmp/oso-codex-smoke.*/main"]` tables from prior runs; `codex exec --help` and `strings` extraction against the installed `codex-cli 0.146.0` binary; three scratch-home, unauthenticated `codex exec` probes against a disposable git repository proving what does and does not suppress project-trust persistence

## Decision

### Part 1 — isolated CODEX_HOME, credentials resolved as option (a)

**The investigation.** `codex exec`'s CLI surface (`--help`, cross-checked against `strings` on the installed binary) offers three candidate suppression mechanisms for option (b) — keep the real `CODEX_HOME`, stop the write instead: `--skip-git-repo-check` ("Allow running Codex outside a Git repository"), `--ignore-user-config` ("Do not load `$CODEX_HOME/config.toml`; auth still uses `CODEX_HOME`"), and a pre-seeded `-c 'projects."<path>".trust_level="trusted"'` override (the generic mechanism ADR-0121 already relies on for `default_permissions`). All three were probed the same way: a disposable git repository under a scratch parent, a fresh empty `CODEX_HOME` with no `auth.json` (so every probe fails on a `401` before any real work happens — no network cost beyond the failed handshake, no real repository touched), `codex exec --json --sandbox danger-full-access -C <repo>`. Measured, unconditionally: the fresh `CODEX_HOME/config.toml` gained the exact `[projects."<repo>"]` / `trust_level = "trusted"` table on every probe, identically whether or not `--skip-git-repo-check`, `--ignore-user-config`, or the pre-seeded override was present. The write happens before authentication is even checked and is not gated by any flag or config key this binary exposes. Option (b) is not honestly available.

**The choice.** Option (a): the smoke builds its own disposable `CODEX_HOME` under `$SMOKE_ROOT` (`populate_smoke_codex_home`, called from `create_integrator_fixture`) and launches `codex exec` with `CODEX_HOME` pointed at it instead of the operator's default. Every write the launch provokes — including the same unconditional project-trust registration measured above — now lands in that disposable directory, which `cleanup_smoke_on_exit`'s existing `remove_temporary_fixture` call already deletes; nothing new to clean up, because the operator's real `config.toml` is never opened for writing by the smoke at all. Option (c) (accept an unauthenticated smoke, record a new frozen loss) is not taken: the login precondition, the real credential and the real delegation all stay exactly as authenticated as before — isolation does not cost that assurance, so nothing here is added to `docs/parity-codex.md`'s frozen loss ledger; the two rows the mechanism actually touches (`User configuration ownership`, `The integrator's git authority`) are corrected in place instead.

**The credential.** `auth.json` is copied, never symlinked, from the real `CODEX_HOME` into the disposable one, with its mode preserved (`600`). A symlink would let the child's own token-refresh write land in the operator's real file — the opposite of isolation, and the exact failure mode "a secret placed outside the protected home with no cleanup path" warns against. The copy is not "outside" anything: it lives inside `$SMOKE_ROOT`, the same tree the smoke already tears down through `cleanup_smoke_on_exit`'s `EXIT` trap on every normal exit, interrupted run included — its lifetime is the fixture's lifetime, not a separate mechanism. The one residual this shares with every other file already in that tree: a `SIGKILL` (or a crash a trap cannot catch) leaves the whole fixture, credential copy included, orphaned under the system temporary directory until an operator or a later run's `mktemp` collision cleans it up — a pre-existing property of the fixture design this decision does not change, named honestly rather than left implicit.

**The rest of the payload.** `hooks.json` and `agents/` are copied from the real installed `CODEX_HOME` (`$HOOKS_FILE`, `$AGENTS_DIR`) rather than re-rendered, so the smoke exercises the `oso-integrator` role and hook wiring that actually shipped, not a second template of it. `config.toml` for the disposable home is produced by calling `render_codex_managed_config` and `render_codex_managed_features` — the same renderer `bootstrap/install-codex.sh` itself uses — never a duplicate. The launch adds `--dangerously-bypass-hook-trust`, the same flag ADR-0094's scratch-home probe already used to run a real hook without reproducing this machine's own separate `[hooks.state]` trust records; the copied `hooks.json` still points at the real, shared, non-secret `$RUNTIME_ROOT/hooks/*.sh` scripts, so what runs is what is actually installed.

### Part 2 — correlation, not token presence

The old `integrator_handoff_consumed` accepted any completed `command_execution` event whose reported command, naively tokenized, contained `oso-state handoff consume` plus a matching-shaped receipt in that same event's stdout — with no reference to whether a spawn had ever happened. Two independent forgeries proved this, driven as fixtures against both the old and the new parser side by side:

- **Token presence with no spawn.** The old parser never inspected `collab_tool_call`/`spawn_agent` events at all. A lone, well-formed `oso-state handoff consume` command plus a matching receipt satisfied it outright — the case the verify criteria name as the one that matters most.
- **A shell comment.** Python's `shlex.split()` does not apply bash's `#`-comment semantics unless told to (`comments=True`, default `False`). A real, genuinely-executed command such as `printf leftover # oso-state handoff consume --slice … --agent-id FORGED …` is a bash no-op — the trailing text never ran — but the old parser's default-mode `shlex.split()` still tokenized it, found `oso-state handoff consume` after the `#`, and treated it as a real invocation.

The fix requires one Codex-assigned agent id to be present in three independent, host-mediated facts, not one self-reported string: a completed `spawn_agent` collab tool call naming that id in `receiver_thread_ids` (a field Codex itself assigns, not text a model or a forged transcript can fabricate merely by writing it), a completed `oso-state handoff wait` reporting a matching receipt, and a completed `oso-state handoff consume` reporting the same receipt — `plugin/bin/oso-state`'s `handoff_wait` and `handoff_consume` both `cat` the identical receipt file on success, so both are checked the identical way. Every `shlex.split()` call — the outer command and the `-c`/`-lc` sub-split — now passes `comments=True`.

**What this can and cannot establish.** `receiver_thread_ids` on a completed `spawn_agent` event is the strongest identity fact this event stream carries: three independent facts — a real spawn, a real wait, a real consume — must now agree on one Codex-assigned id, not a string one command's stdout claims. What it cannot establish is which custom role that spawned id actually ran as: Codex 0.146.0's JSON stream never names the selected `agent_type` on the spawn event itself, the exact boundary ADR-0100 already recorded for the profile-identity claim on this same smoke. This check proves a real delegation happened and its output was genuinely consumed, not that the delegate specifically carried the `oso-integrator` role — the smoke's separate, unchanged assertions (the landed merge, the removed worktree, the deleted branch) are what tie that delegation to real integrator work, exactly as before.

**Proof, not assertion.** Twelve fixtures — a fully correlated positive control; the falsified consume-with-no-spawn case; the comment-forged consume; a decoy spawn id; a consume with no genuine wait; a spawn with no consume; a bare report line; and five receipt/field-mismatch cases carried over from the prior parser — were run against both the pre-fix and the post-fix parser, extracted directly from `bootstrap/verify-codex.sh` via `sed`, in an isolated bash process with no `codex`, no network and no real `CODEX_HOME` involved. The four cases that name the actual defects (no-spawn, comment-forgery, decoy-spawn, no-wait) report `observed` against the pre-fix parser and `missing` against the post-fix one; the rest agree both ways. `tests/hooks-test.sh` carries the same fixtures.

### Part 3 — the nine orphan tables

`~/.codex/config.toml` was backed up first (`cp -p`, preserving the `600` mode; the backup's hash was re-verified against the live file immediately before and immediately after the removal pass to refuse publishing over a concurrent change). The nine tables whose header matched the smoke's own shape exactly — `^\[projects\."/tmp/oso-codex-smoke\.[A-Za-z0-9]{6}/main"\]$` — were removed one at a time with `bootstrap/lib/toml-regions.awk`'s existing `remove-table` action (the same primitive `cleanup_smoke_project_config` used, reused rather than re-implemented), never a hand-written second TOML editor. A `diff` between the backup and the result shows only those nine three-line blocks (header, `trust_level`, blank separator) removed — 27 lines total, 174 → 147 — and every other byte, including the seven real project trust entries, all thirteen `[hooks.state]` entries and the `mcp_servers`/`marketplaces` tables, untouched. The result parses cleanly under Python's `tomllib`.

## Consequences

- A future authenticated smoke run can no longer write to the operator's real `config.toml`: the write target is a disposable directory the fixture's own existing teardown already removes, so the class of defect measured here (nine accumulated orphans) cannot recur through this mechanism.
- `cleanup_smoke_project_config` and its dedicated `tests/hooks-test.sh` structural case are deleted as dead code; nothing replaces them, because there is no longer a per-run write to clean up.
- The authenticated smoke's evidence is strictly narrower than "the child ran as `oso-integrator`" and always was (ADR-0100); this decision makes that boundary load-bearing in the parser itself instead of leaving a claim the event stream cannot support.
- CI's pinned `verify-codex.sh` failure count is unchanged: reproducing `.github/workflows/ci.yml`'s exact fixture (a fresh `HOME`/`CODEX_HOME`, `OSO_VERIFY_SKIP_SMOKE=1`, `codex` absent from `PATH`) still reads `passed: 1, failed: 14` — every function this decision touches runs only on the non-skip path `OSO_VERIFY_SKIP_SMOKE` bypasses entirely.
- `docs/parity-codex.md`'s "User configuration ownership" and "The integrator's git authority" rows are corrected to describe the isolated `CODEX_HOME` and the spawn/wait/consume correlation in place of the retired per-run cleanup and the token-presence check.
- The operator's real `~/.codex/config.toml` carries seven real projects, unchanged `[hooks.state]` trust entries and MCP wiring, and zero orphan smoke tables; a byte-identical pre-cleanup backup remains at `~/.codex/config.toml.pre-orphan-cleanup.20260806-094327.bak`.
