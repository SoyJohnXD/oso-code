# 0108 — Deny records name what they denied, with a schema version

Date: 2026-08-05
Status: accepted
Implemented-in: plugin/hooks/lib.sh, plugin/hooks/block-unknown-tool.sh, plugin/hooks/block-edits-without-slice.sh, plugin/hooks/block-commit-until-green.sh, plugin/hooks/capture-plan-approval.sh, bootstrap/hook-hashes.txt, tests/hooks-test.sh, docs/blueprint.md
Superseded-by: ADR-0111 — retires only the claim that the command line reaches `deny_until_green` through its "new second argument"; ADR-0111 gives `deny_until_green` a `state_file` second argument for its mode-aware remedy, so `command` is now third. Everything else this decision records — the fourth `detail` argument on `deny()`, the `schema`/`gate`/`hook_event` fields, and the six named `stop_block` causes — stands unchanged.
Reconciled: superseded — the one clause above now reads otherwise; the rest of this decision is still exactly what the code does.
Source: `~/.local/state/oso-code/events.jsonl` — 2540 real events, every one of the 63 `commit-denied`, 9 `edit-denied` and 8 `unknown-tool-denied` lines carrying `"command":""`, and ten of the fifteen operator-visible Stop blocks in the real transcripts reading the identical sentence `malformed plan approval marker; emit it exactly once as the final line of a non-empty plan document.`

## Decision

**A deny records what it denied.** `deny()` took `reason event session` and called `log_event "$event" "$session"` — two arguments, so `log_event`'s third `command` parameter, and the UTF-8-safe `command_head` bound built for it, were unreachable from every deny. `deny()` now takes an optional fourth `detail` argument and passes it through as `log_event`'s command field, preserving the existing invariant that the verdict prints before anything that can fail and that `trap - ERR` stays where it was. Its three PreToolUse callers now pass what they already have in hand: `block-unknown-tool.sh` passes the tool name, `block-edits-without-slice.sh` passes the file path (read only once a deny is already decided — the verdict itself still reads only state flags), and `block-commit-until-green.sh` passes the exact command line already computed for the verdict, through `deny_until_green`'s new second argument. No second truncation is invented: `command_head`'s existing 120-byte bound, backing up off a split UTF-8 continuation byte, is what every one of these three details is written through, because it is already the bound the log's privacy budget was sized against.

`deny_unusable_state` keeps its unchanged, argument-less call: the state file path it denies over is already named in the reason text the operator reads, and no ledger decision asks for a second copy of it in the audit line.

**The record is structured and versioned.** `log_event` gains a `schema` field (`EVENTS_SCHEMA_VERSION=2`) on every line it writes, so a later reader can tell a schema-1 line from a schema-2 one without inferring a shape from which keys happen to be present — `events.jsonl` rotates on a 30-day mtime, not on release, so both shapes coexist in the same file for as long as that window.

It also gains two optional fields, `gate` (the hook script that fired — `${0##*/}`, the same free-handle idiom already used for the `client` field) and `hook_event` (the native hook event the call arrived on). Both are additive, appended after the existing five fields, never inserted between them, because three existing tests assert `"event":"X","command":"Y","session":"` as one adjacent substring and `oso-state`'s own `event` verb writes through this exact function. Only a deny pays for them: `deny()` sets `hook_event=PreToolUse` once, since every one of its callers — the catch-all, the slice gate, the commit gate — is a PreToolUse matcher by construction (verified by `hook-gates.txt`'s own `expected_event` table, not duplicated here), and `capture-plan-approval.sh`'s `stop_block` sets `hook_event=Stop` the same way, since that file is wired to nothing else. Neither is a second copy of the gate↔event mapping `tools/render-hooks-json.sh` already owns: each is one literal, local to the one function whose calls are all provably that event, read off the same fact the client-facing JSON already asserts in that call.

Everything else that already called `log_event` — `oso-state`'s `set`/`event`/`clear` verbs, the commit gate's `residue-allowed` count, worktree lifecycle and handoff events — passes neither new field and keeps the exact five-field shape schema 1 had. This is what keeps the event log's size budget from growing on its highest-volume, longest-command lines: `residue-allowed` can carry a full 120-byte command head already, and a `commit-denied` line now can too (it could not before this decision, since its command field was always empty). Widening every line uniformly would have pushed the worst realistic case in the suite from 264 to over 340 bytes; scoping the two extra fields to deny-shaped calls keeps that growth on the lines it is meant for.

**A command head is a name, never a copy.** `command_head`'s 120-byte, UTF-8-safe cut is unchanged and deliberately kept: D10 named it a deliberate design, not an oversight, and widening it — or any new field — into secret territory was explicitly ruled out. No field this decision adds may carry a file's contents, a plan's text, or an untruncated command; the tool name and file path are themselves bounded the same way as a defensive measure, not because either is expected to exceed it. The event log stays owner-only (`umask 077`), and a deny is diagnosable from `gate` + `hook_event` + the existing `event` reason code + a bounded `command`/detail — never from the operator's actual work.

**Existing third-argument callers keep their meaning.** `approve-plan-token.sh` logs `$cancel_error`/`$control_error` and `capture-plan-approval.sh`'s `stop_block` logs `$capture_error` through the same third `command` parameter `log_event` always had — that parameter carries whatever diagnostic text a caller has, error text or a command line alike, and this decision does not repurpose it. Those two files are otherwise untouched by this decision beyond `stop_block` gaining `gate`/`hook_event`, described above.

**Six marker failures name six structural causes.** `capture-plan-approval.sh` had six `stop_block` call sites sharing one sentence — `malformed plan approval marker; emit it exactly once as the final line of a non-empty plan document.` — despite detecting six different things: the marker's position and count in the raw message; a marker-only message lacking transcript attestation; zero or more than one matching Plan item; a turn/thread mismatch on the one Plan item found; empty Plan text; and the Plan item's own text carrying a marker. Each now reads its own cause. The strings name the structural cause only, never plan text, transcript content, session ids or paths — they reach the operator's transcript, and D10 already requires operator-facing messages to name the specific cause without widening what they disclose. The corresponding event detail may carry more, since the log is owner-only, but none of the six sites was given one: none has a short, non-content fact worth naming beyond the reason code itself.

## Consequences

- A denied tool call, edit or commit names the tool, path or command in the audit line, not just that a deny fired — the gap that cost the operator a UI-only diagnosis of a `mem_judge` denial is closed.
- `events.jsonl` carries a `schema` field on every new line, so a consumer written after this slice can tell a schema-1 record from a schema-2 one during the 30-day window both shapes coexist in the file.
- A deny is now diagnosable from the log alone: which gate fired, on which hook event, with what reason code and what it denied — without opening the Codex UI transcript.
- The event log's byte budget stays tight for its highest-volume lines (`residue-allowed`, `oso-state`'s own verbs), because only deny-shaped calls carry the two new structural fields.
- Six previously identical Stop-block sentences are six distinct ones; a future collapse back to one sentence is caught by a test that asserts the six drives produce six different reason strings, not by a human noticing a corridor got quieter.
- `command_head`'s bound and its UTF-8-safety are unchanged and now actually reached by every deny path, closing the gap that made it dead code.
