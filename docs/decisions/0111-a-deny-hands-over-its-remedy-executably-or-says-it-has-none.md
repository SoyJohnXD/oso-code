# 0111 — A deny hands over its remedy, executably, or says it has none

Date: 2026-08-05
Status: accepted
Supersedes: ADR-0108 (only its description of the command line reaching `deny_until_green` through "its new second argument" — `deny_until_green` now takes `state_file` second and `command` third; every other line of ADR-0108 stands)
Reconciled: applied — `lib.sh` gains `oso_state_remedy()` and a mode-aware `deny_until_green()`; the three PreToolUse gates each carry a `# Recovery:` header line and a deny reason ending in a concrete next step; `block_with_gate_error` says explicitly that no remedy is known; `tools/render-hooks-json.sh`'s table parser rejects a PreToolUse gate script with no declared recovery route, and `tools/hook-gates.txt`'s header records the rule next to the gate rows it governs.
Source: the operator's own complaint that the harness "me manda hacia atrás en vez de recuperarse hacia adelante"; the pre-freeze doubt pass on the codex-fluidity ledger, whose verdict on the twenty prior decisions was that "the change can land complete, meet its bar, and leave the operator's lived experience of being blocked substantially unchanged"; A6 (`349ea70`, ADR-0108) which made a deny name what it denied but not what would undo it

## Decision

**A gate that knows the remedy hands it over, executably; a gate that does not know it says so.** Every PreToolUse gate already holds the information the operator needs to recover, and before this decision none of them spent it: `block-edits-without-slice.sh` denied "no slice is active" without the session id its own remedy needs; `block-commit-until-green.sh` (through `lib.sh`'s shared `deny_until_green`) offered a two-way menu — "the verify loop (plan mode) or the quality pass (quick mode)" — that the operator had to translate into the one path their own session was actually on, and never named debug mode at all; `block-unknown-tool.sh` gave a pending plan approval two concrete escapes but gave an unlisted tool none. `deny_unusable_state` was the one exception already: "Remove or repair it (`oso-state --session ${session} clear`), then retry" is a command, not a description, and this decision is the other three gates reaching that same shape.

**The remedy rides in `deny()`'s `reason` argument, never in `detail`.** A6 (ADR-0108) added `deny()`'s fourth `detail` parameter and wired it solely into `log_event`'s `command` field — the audit trail, bounded by `command_head`'s 120-byte cut, read only from `events.jsonl`. The JSON `permissionDecisionReason` — the value of `reason`, the first argument — is the only thing either host ever shows past a deny: Claude Code feeds an exit-0 hook's JSON straight into its permission decision, and Codex's own `PreToolUse` handler reads `hookSpecificOutput.permissionDecisionReason` as the `Feedback` entry it surfaces. A remedy placed in `detail` would be truncated for an audit log nobody but the maintainer reads and would never reach the operator at all. This settles the three-way question the slice payload posed (ride in `detail`, beside it, or in `reason`): only `reason` is read by anyone the remedy is for.

**One shared helper formats the one piece that repeats.** `oso_state_remedy(session, verb_and_args)` in `lib.sh` prints `oso-state --session <session> <verb_and_args>` — the exact binary name and `--session` spelling `deny_unusable_state` already used, now shared with `block-edits-without-slice.sh`'s new remedy (`set active_slice=<n>`), so the operator never sees two different spellings of the same call for two different denials. This is deliberately narrow: not every remedy is one `oso-state` write. `deny_until_green`'s remedy is a flow to resume, not a state write — the flag it must set is a side effect of the checks passing, and printing that state write as the "remedy" is exactly the bypass this decision forbids (below). `block-unknown-tool.sh`'s allowlist remedy is a fact the gate already holds (the allowlist itself), not a command. Both are composed as plain reason text at their own call sites; forcing them through `oso_state_remedy` would misrepresent what they are.

**`deny_until_green` reads the session's own `mode` and names that mode's own step.** `block-commit-until-green.sh` and `plugin/git-hooks/pre-commit` both already resolve `state_file` before calling it; `deny_until_green` now takes it as a second argument (`session`, `state_file`, `command`) and reads `state_value "$state_file" mode` to pick exactly one of: plan mode's "apply → verify loop" (the term `plan.md` §6 and its own cross-references already use), quick mode's close step, or debug mode's close step. A mode the gate cannot read — absent, or a future mode this case statement has not met yet — falls back to naming every route rather than guessing one, so the fallback is honest about not knowing which flow is active without ever going silent. This is the literal fix for the operator's complaint: the harness now answers "which flow am I actually supposed to finish" from state it already holds, instead of handing back a menu every time.

**The remedy for "verify is not green" is never `verify_green=true` itself.** The constraint that outranks every other design choice here: a remedy that told the operator to write the flag directly would turn this decision into a documented bypass. None of the three rewritten remedies, and none of `deny_unusable_state`'s, name a state write that disarms the gate it belongs to — `deny_until_green`'s three mode branches each name the checks to run, never the flag those checks flip; `block-edits-without-slice.sh`'s remedy arms a slice, which is what the gate is waiting for, not a shortcut around it; `block-unknown-tool.sh`'s allowlist remedy names tools already permitted, nothing the gate itself denies. `tests/hooks-test.sh` asserts this directly: every remedy string captured across all three gates and all three commit modes is scanned for the literal substring `verify_green=true`, strict enough that reintroducing it anywhere turns the suite red.

**`block-unknown-tool.sh`'s two causes get two remedies, because they are two different problems.** A pending plan approval and an unlisted tool are unrelated failures with unrelated fixes. The pending-approval message already named Codex's native controls ("Implement the plan." or `CANCEL OSO PLAN`) and is unchanged by this decision. The allowlist denial previously named nothing; it now enumerates the exact allowlist this release admits (`Use one of the allowed local tools instead: <list>`), read off the same `$allowlist` variable the gate already validated at start-up — no new state, no guess. `tests/hooks-test.sh` asserts the two reason strings are never equal, so a future collapse into one shared sentence goes red.

**Where a gate genuinely has no remedy, it says so.** `block_with_gate_error` — the shared exit-2 path for a crash mid-gate or a malformed installer config (a missing `sha256sum`, an empty or invalid Codex allowlist argument) — covers failures with no single operator-actionable fix: which one applies differs by cause, and several are installer bugs no retry or command resolves. Its message now states plainly that no remedy is known, rather than describing the failure and leaving the operator to infer that nothing can be done about it. Inventing a plausible-sounding but wrong remedy here (e.g. "retry the call") was considered and rejected: it would be correct for a transient crash and actively misleading for a static misconfiguration, and this decision's own constraint — never guess an ambiguous remedy — applies as much to this shared path as to the deny-shaped ones.

**A new PreToolUse gate declares its recovery route or it does not land.** Every PreToolUse gate script now carries a `# Recovery:` header comment naming its own way out, or explicitly stating there is none. `tools/render-hooks-json.sh`'s table parser enforces this mechanically: a `gate` row whose event is `PreToolUse` and whose script has no line matching `^# Recovery:` fails `parse()` — which every mode (`--check`, `--write`, `--host`, `--classify`) runs before doing anything else — the same way a missing matcher or a missing script already fails closed. The rule is recorded in `tools/hook-gates.txt`'s own header, in the same register as its other structural invariants (row order, the meaning of `none`, the command-root quoting), immediately before the `gate` rows it governs — not in `tests/plugin-lint.sh`, which is slice B6's territory for a lint rule per ledger decision; this is a narrower, mechanical invariant about one column of one table, already owned by this table's own parser. The check is deliberately scoped to `PreToolUse`: that is the event whose contract is `deny()` — the mechanism this whole decision is about. `Stop` and `UserPromptSubmit` gates (`capture-plan-approval.sh`, `approve-plan-token.sh`) block through `stop_block`/`control_block`, a different channel with its own remedy shape (D18's pending-plan-amendable-in-place half, slice B2) that this rule does not reach yet; `SessionStart`/`SessionEnd`/`SubagentStop` gates (`persist-state-bin.sh`, `warn-stale-state.sh`, `cleanup-state.sh`, `publish-subagent-handoff.sh`) never deny a call at all, so requiring a recovery route from them would be a declaration with nothing to recover from.

## Consequences

- An operator (or a model reading the deny back to them) denied for a missing slice, a red commit gate, or an unlisted Codex tool now reads a concrete next step naming the real binary, the real session, and — for the commit gate — the exact flow their own session is on, not a menu or a description of one.
- `deny_until_green`'s signature changed (`session`, `state_file`, `command`); both callers (`block-commit-until-green.sh`, `plugin/git-hooks/pre-commit`) already resolved `state_file` before calling it, so no new lookup was added to either.
- `oso_state_remedy` has exactly two callers (`deny_unusable_state`, `block-edits-without-slice.sh`) — the two remedies that are genuinely one `oso-state` invocation; it is not forced onto remedies that are a flow to resume or a fact to state, which would have misrepresented them as commands to run.
- `block_with_gate_error`'s message is honest about carrying no remedy, closing the one path in this slice's scope where inventing one would have been guessing.
- A future PreToolUse gate that ships without a `# Recovery:` header fails `tools/render-hooks-json.sh`'s table check immediately, before a render or a hash check ever runs — the declaration is a build-time gate, not a code-review convention that can quietly lapse.
- `tests/hooks-test.sh` gained a strict, standing assertion that no remedy captured from any of these gates or modes ever contains the literal state write that would disarm its own gate — a security regression there is a red suite, not a design-review catch.
- The pending-plan-amendable-in-place half of D18 — `approve-plan-token.sh`'s feedback-invalidation path, and `capture-plan-approval.sh`'s `stop_block` sentences — is unchanged by this decision; it remains slice B2's.
