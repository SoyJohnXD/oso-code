## 0. Purpose, principles, non-goals, end state

**Purpose.** Lower the rate at which a slice fails its first verification by making the applier PROVE behaviour instead of running commands; make the verifier's rigor independent of the model it runs on by moving every gate that can be mechanical out of the model's judgment and into a validator every host shares; record every verdict so the harness is tuned from numbers; bound the apply → verify loop; let the operator choose the model per role on OpenCode as on Claude, with a plan approved on one host executable on another; and make an OpenCode run prompt-free for everything the harness already decides, so an unattended run there stops on a decision and never on a permission dialog.

**Principles (the operator's, 2026-09-01) and how this document reads each one.**

- *Efficiency* — no fix round spent learning what a validator could have said at the seam; no probe re-derived that a confirmed claim already carries; no slice relaunched to collect a verdict a child already gave.
- *Speed* — nothing added to the hot path costs more than milliseconds; telemetry never blocks; a guard fires only on a malformed or contradictory output, so a well-formed run never pays for it.
- *Rigor* — what the plan says gets done: every criterion answered by name, every ledger decision cited by id, the rubric's four no-exception rules enforced by a scan the verifier cites, and a failing check that names a file the slice actually touched or an exception the plan actually declared.
- *Reinforced discipline on every host* — one parser, one validator, one record on Claude, Codex and OpenCode; a rule a host cannot enforce mechanically is written as a degrade with its event, never assumed.
- *Not clunky* — no new operator question in any flow, no new prose rule, no new gate that an LLM judgment arms; every refusal names its remedy (ADR-0111) so the next launch carries the fix instead of a guess.
- *No coded debt* — one module per guard in the core, rendered to each host by the build; no per-host copy; no inline comments; nothing kept "for later" in the tree.

**What does not change.** The flows and their phases, the independent verifier and its authority, the rubric's four no-exception rules, the state keys and their file format, what each gate denies, `events.jsonl`, the run journal, the engram topics, the sweep's judge → fix loop (ADR-0130, ADR-0131), the three hosts, the operator's own permission rules in their host configs.

**Non-goals.** No cheap model runs inside this roadmap's own execution (G6). No new gate that fires per slice on an LLM judgment. No new operator question in any flow. No ADR per slice. No mutation testing, RED-at-SLICE-START or harness-generated checklist unless C5's thresholds say so. No change to what any flow asks or decides.

## 1. Facts the design stands on (verified 2026-08-28 and 2026-09-01, with where)

## 2. Global ledger (applies to every child unless a child says otherwise)

**G1 — When and on what. DECIDED, amended in revision 3.** Armed after `ts-core-rewrite` C5 is merged to `main` and the merged tree is installed on this machine per §7 precondition 1; C6 `rewrite-release` runs AFTER this roadmap, as the one release carrying both. Every change edits the TypeScript core and the ONE source each skill and agent has after the rewrite's C5 (rendered to Codex and OpenCode by the build) — never a per-host copy.

**G2 — Additive by construction. DECIDED.** No new prose rule, no new operator question in any flow. Every addition is a schema field in a report, a validator in the core, a script, or a config row the installer owns. Telemetry never blocks: a failed write logs one event and the run continues. A missing input degrades to today's behaviour and says so. A guard fires ONLY on a malformed or contradictory output, and its refusal names the exact line or token that would have passed (ADR-0111): a well-formed run never meets a guard.

**G3 — What stays. DECIDED.** The rewrite's §6 list is inherited whole: phases, gates and what they deny, state keys and format, `events.jsonl`, the journal, the engram topic keys, `docs/decisions/` as history. The rubric's four no-exception rules stand as they are. One vocabulary change is made on purpose and only in C3: a slice may end its apply → verify loop as `escalated`. One state-write refusal is added on purpose and only in C2: `verify_green=true` over a recorded `fail`.

**G4 — Tiers. DECIDED.** The verifier never runs on a weaker model than the applier of the same slice; the forked judges stay on the strong tier. C0 makes the tier selectable AND enforces this floor at install (the profile refuses a custom that puts the verifier below the applier); C2 records the model per launch so the floor is measurable.

**G5 — Baseline and targets. DECIDED.** The "before" is the journal count of 2026-08-28 and the OpenCode store reading of 2026-09-01 (§0 table). The "after" is what C2's `oso report` reads. A child that misses its target closes with the number in its report — never with a softened target — and the presence phase carries it.

**G6 — Models of this run. DECIDED, amended 2026-09-04 (revision 3, the operator).** The orchestrator, `oso-applier`, `oso-verifier` and every judge run on `opus`, at every launch, the model named in the announcing sentence. Reason: the operator's budget is one day; rounds decide the bill and not the applier's price (engram `oso/applier-fail-diagnosis`), and the FAIL classes a stronger model shrinks — A unexercised, B rule-in-hand, E false self-report — are 67 % of the measured FAILs. Fallback, never a stop: an applier or judge launch that dies on the host's rate limit (HTTP 429) is relaunched ONCE for the same role on `sonnet` for that launch only, journaled as `model-fallback: <role> <slice> opus→sonnet`, counted as the same attempt; a verifier launch that dies the same way WAITS for the window and is relaunched on `opus`, because G4 forbids a verifier weaker than the applier of its slice and every applier here ran on opus. No cheap model executes any slice of this roadmap: C0 makes them selectable, C2 measures, the operator's later runs decide.

**G7 — Fix rounds of this run. DECIDED.** Two fix rounds per slice; at the cap the orchestrator stops and puts the three routes of ADR-0130 to the policy or the operator. C3 makes this the default of the flows.

**G8 — Record. DECIDED.** English. Conventional commits, no AI attribution. No ADR per slice: each child's frozen ledger, the PR body and the roadmap record are the record; one closing ADR for the whole roadmap is the operator's call at the presence phase, never a child's.

**G9 — The verdict record shape (written by C2, read by C1's and C5's targets). DECIDED.** One JSON line per launch report the harness reads, under `runs/<repo digest>/<change>.verdicts.jsonl`, private mode, append-only, never rotated. Fields, named after the OpenTelemetry GenAI attribute where one exists and `oso.*` otherwise: `time`, `gen_ai.agent.name` (applier | verifier | integrator | judge name), `gen_ai.request.model` (as launched, or `unknown`), `gen_ai.usage.input_tokens` / `output_tokens` (only when the host reports them), `oso.host` (claude | codex | opencode), `oso.session`, `oso.change`, `oso.slice`, `oso.attempt`, `oso.mode` (sequential | parallel), `oso.launch_outcome` (reported | empty | timeout | refused), `oso.status` (done | blocked | none), `oso.verdict` (pass | fail | blocked | none), `oso.verdict_shape` (valid | malformed | none), `oso.findings.blocker` / `structural` / `nit` (counts), `oso.criteria.asked` / `answered`, `oso.claims.confirmed` / `refuted` (from C1), `oso.failing_check` (new-or-extended | pre-existing/missing | exception-declared | none), `oso.failing_check_quality` (independent | tautological | implementation-coupled | none), `oso.probes` (count of `cmd:` evidence lines), `oso.probes_executed` (count of tool calls the host logged for the child, or `null`), `oso.duration_ms` (launch to report where the capture point knows both), `oso.escalated` (bool, from C3). Unknown is `null`, never invented.

**G10 — Cross-host trust. DECIDED.** An approval artifact written by one host is honoured by another ONLY through that host's own grant (OpenCode: `oso_plan_approve` on the found snapshot; Codex: its native approval). A file is evidence of what was approved, never the approval.

**G11 — Prompt-free for what the gates decide. DECIDED.** On OpenCode the plugin answers a host permission prompt whose answer a harness gate already holds, with that gate's own verdict and reason: the harness's own paths are never a foreign directory; a `git commit` is allowed exactly when the commit gate would allow it; a push of the run's own `oso-run/<change>` branch under `auto=running` is allowed exactly when the production boundary would allow it. The plugin never widens what a gate denies, never answers a prompt no gate covers, and never touches the operator's own rules. What remains a prompt under a posture is PRINTED by `oso profile show`, so an operator arming AUTO on OpenCode reads what can still stop the run before it starts.

**G12 — One grammar, one validator. DECIDED.** The report and verdict grammar lives once in the core (`core/src/verdict/`): the parser, the shape validator and the record writer are the same module on the OpenCode launch seam, in the Claude and Codex SubagentStop gates, in the structural tests that pin every call site, and in `oso report`. A host renders nothing of its own; a contract change edits the grammar and the two agent sources, and the verdict-grammar test refuses a call site that drifts.

**G13 — Run discipline of every launch. DECIDED 2026-09-04 (revision 3, the operator), from the measured FAIL classes (engram `oso/applier-fail-diagnosis`: A unexercised 30 %, B rule-in-hand 29 %, C payload 17 %, F test quality 14 %, E false self-report 8 %; 81 % catchable by the applier, 17 % the orchestrator's own).** Until C1 makes them mechanical, the orchestrator applies them BY HAND in every payload, on every host: (1) the ledger decisions a payload cites are copied VERBATIM by id from the ledger record, never paraphrased and never quoted in part (class C); (2) every slice payload names its failing-check path or its `Verify-exception`, as this document's slice lines already do, and asks the applier for proof per Verify criterion — the probe that exercises the behaviour, what was observed, and the failing check's output RED before implementing and GREEN after (classes A, E, F; the practice of the `datos-y-roles` run, where the applier produced them when its payload asked); (3) a fix-round payload carries the verifier's finding verbatim and names the CLASS the finding belongs to, and the applier fixes every member of that class in the slice's diff, never the one instance (the rule that held on C4 and C5 of the rewrite); (4) a verifier finding outside the slice's criteria and the project's bar is routed to the child's close sweep, never to a fix round (the verifier's remit; G12 of the rewrite). None of these is a new sentence in any contract: they are payload contents and routing, stated in the arming instruction of §7 and carried by the roadmap record into every child's plan.

## 3. The queue

### C0 — `host-posture`: the model per role, the closed tool surface, and no prompt for what the gates decide

**Intent.** Before any applier proves anything, make the OpenCode host honour G4 and stop stopping. Capability and posture only: no flow changes what it asks or decides. Ordered first because the operator's next cheap-model runs happen on this host, and today every role there runs on the session model behind prompts a headless run auto-rejects.

**Decisions.**
- C0-D1: `oso/preferences` gains `model_profile`: `normal` (applier and verifier on the default tier, judges strong), `strong` (all three strong), or `custom` (`applier`, `verifier`, `judges` named per host's spelling; `oso profile set` refuses a custom whose verifier tier is below its applier tier — G4 at install). Read silently at §0 like the other fields; changed by the same natural-language update; never a question in any round (G2). `oso profile show|set <name>` writes the record's mirror and the host configs. The profile also carries `unattended.doom_loop` — DECIDED by the operator on 2026-09-01: `ask`, on every host posture, so an unattended run on OpenCode can still stop on the host's own loop brake and `oso profile show` lists it; `allow` stays a value the operator may set later, never a default a child writes.
- C0-D2: Claude honours the profile at launch: the `model:` the Agent tool takes, named in the announcing sentence (G6's practice made the rule).
- C0-D3: OpenCode honours it at install: the installer writes `agent.oso-applier.model`, `agent.oso-verifier.model` and `agent.oso-<judge>.model` from the profile into the keys it already owns, leaf-merged, the rest of `opencode.json` untouched (parity ledger D24). Codex keeps its pinned roles; the profile records `codex: pinned by host contract` and implies nothing. (The per-launch `model` on `oso_launch` / `oso_wave` is C4-D3: it needs C2's seam.)
- C0-D4: the closed tool surface. Each `opencode/agents/*.md` permission block denies, by server-prefix wildcard, every MCP server the installed config declares except the servers that role's Claude twin lists (`plugin/agents/*.md` `tools:`, and the judges' skill frontmatter): the applier keeps `context7_*`; the verifier, the integrator, doubt-pass, triage, security-reviewer and quality-pass keep none; the debt-sweep keeps the read-only `fallow_*` tools it uses and keeps `fallow_fix_apply` denied. The block is RENDERED from the Claude source by the build (G1) and `oso verify` on OpenCode asserts, per agent, that no server outside the twin's list is reachable. The engram "mandatory protocol" text that reached the DeepSeek children through the server is thereby unreachable to them — the fix is the surface, not a sentence.
- C0-D5: the prompt-free posture, two halves. (a) Config rows the installer owns, leaf-merged: `permission.external_directory` allows the harness's own paths — `~/.config/opencode/**`, `~/.local/state/oso-code/**`, `~/.local/share/opencode/worktree/**` — and nothing else; the operator's own trees stay theirs to allow. (b) The plugin's `permission.ask` hook (its shape measured at S3's §2 against the installed host; if the hook proves absent or shapeless there, the config rows carry (a) alone, the two answers below stay prompts, and the divergence is recorded — G11's risk row) answers exactly three prompts with a gate's verdict: `git commit` → the commit gate's own predicate (allow when `verify_green=true` for this repository, else deny with the gate's reason); `git push` of `oso-run/<auto_change>` while `auto=running` → allow, any other push → untouched; `doom_loop` → the profile's `unattended.doom_loop`. Everything else passes through untouched.
- C0-D6: `oso profile show` prints, from the rendered config, the prompts that REMAIN under the posture (the operator's own `ask` rules, `doom_loop` when `ask`, `oso_plan_approve`, `oso_plan_cancel`), so "unattended on OpenCode" is a list the operator reads and not a hope.

### C1 — `applier-proof`: the applier proves behaviour, the verifier confirms claims after its own probing, the diff is self-scanned, the plan names its check

**Intent.** Turn the applier's report from "commands I ran" into "what I proved, how, and what I scanned"; make the verifier's reading of those claims a reconciliation AFTER its own probing, never an anchor before it; and refuse at capture a plan whose slice names neither a failing check nor an exception. Targets (G5): first-fail rate ≤ 25 %; E-class FAILs ≈ 0; inline-comment FAILs ≈ 0; C-class halved.

**Decisions.**
- C1-D1: the applier report gains `proof:` — one entry per Verify criterion of the slice: `criterion`, `probe` (the exact command, request or action that EXERCISES the behaviour — the project's bar is not a probe), `observed` (what came back), and on the slice's failing check two more lines, `red:` (the check run BEFORE the implementation existed: command, exit, one line of output) and `green:` (the same after). A criterion with no probe is reported `proof: none — <reason>`, never omitted. Under PARALLEL the project's bar stays skipped as today; probes that need only the slice's own files and processes stay required; a probe that needs the shared bar is `deferred: parallel`.
- C1-D2: RED-before-GREEN is an ORDER of work, not a revert. The applier writes the failing check first, runs it, records the red, then implements. No checkout, stash, restore or rebuild. A `Verify-exception` slice reports `red: exception — <the Verify line's reason>`.
- C1-D3: the mechanical self-scan. Before reporting, the applier runs `oso scan comments <ref>` (the comment scan the verifier's empirical gate runs today, shipped once in the core, language-generic, output cited) and on TypeScript/JavaScript projects `oso scan abstractions <ref>` (exports with fewer than two callers inside the diff, via fallow where configured, a reference count otherwise). Hits are fixed before the report or listed under `scan:` with the one reason that stands. The verifier's own scan stays — independence — and now also compares against `scan:`.
- C1-D4 (order changed from revision 1): the verifier runs the slice's criteria and the project's bar on its own FIRST, and only then reconciles the applier's claims — re-running each `proof` probe or an equivalent — and its verdict gains `claims:` lines: `<criterion>: confirmed | refuted — <how>`. A refuted claim is a finding and fails the slice. The verifier receives the `proof:` BLOCK as the one added payload field, `applier_proof`, verbatim — the block only, never the applier's narrative or the rest of its report: a judge that reads the author's story first agrees with it (judge-bias evidence in `oso/harness-practice-evidence`; the DeepSeek verifiers that "sampled" citations are what a claim of "script X resolved 77/77" would have turned into a full re-run). The closed payload list (ADR-0142) grows by exactly that field.
- C1-D5: the decisions block of the applier payload is copied from the ledger record BY ID, verbatim, never paraphrased; the verifier receives the same block; a `decisions_used` id absent from the block is a finding.
- C1-D6: the two contracts are rewritten AROUND the schema and get no new rule sentence (G2): the output schema comes first; one worked example each — a `done` report carrying `proof`, and a `fail` verdict carrying `claims` with one refuted line — because a weaker model copies a shape it has seen far better than it follows a paragraph; the verifier's gates are a numbered list it answers one by one in `criteria:`; no sentence over 60 words; the contract's rule-sentence count is asserted not to exceed today's. The verdict-grammar test of the rewrite's C5 covers the new fields at every call site.
- C1-D7 (new): the plan's Verify line is validated at capture. Every slice block of an approval document carries either `failing-check:` naming a path, or `Verify-exception: <reason>` — the two tokens plan.md §4 already requires. `capture-plan` (Codex and OpenCode today; Claude once C4-D1 gives it the artifact) refuses a document whose slice carries neither, naming the slice; the orchestrator corrects the document and re-presents it through the material-change lane that already exists. Degrade: a document with no slice blocks is not validated. The 2026-09-01 plan would have been refused at the grant, before six verifiers had to invent a check.

**Proposed slices.**
- S1 (opus) — the two contracts on the one source: applier `proof` / `scan` schema, the worked examples, the verifier's numbered gates, the `claims` reading in its post-probing place and the `applier_proof` payload field; Codex and OpenCode renders regenerated. Verify: `npm test` green; the verdict-grammar test names `proof`, `scan`, `claims`, `applier_proof` at every call site; the rule-sentence count test holds; failing-check: the grammar test fails on an applier report without `proof`. Depends-on: none.
- S2 — `oso scan comments|abstractions <ref>` in the core with fixtures per language the rubric names. Verify: fixture with `// D22: retries cap at 3` flagged, JSDoc public-API form not flagged, `#!` and license headers not flagged; failing-check: a fixture the scanner must flag and does not without the slice. Depends-on: none.

### C2 — `run-telemetry`: every launch is one line the harness can count, every verdict has a shape, and green needs a receipt

**Intent.** Capture the G9 record at the seams that read reports, on every host, at no cost to the run; validate the shape of what a child returned before the orchestrator reads it; count what a verifier actually ran beside what it said it ran; and refuse a green that contradicts the record. - C2-D4 (new): verdict-shape validation at every seam, from the one validator (`core/src/verdict/validate.ts`). A verifier report is VALID when it carries `verdict:` with a vocabulary value; at least one `cmd:` line; at least one `criteria:` line; a `failing-check <name>: <value>` line whose value is in the vocabulary and whose `<name>`, when the value is `new-or-extended-by-this-slice`, is a path present in `git diff --name-only <SLICE START>` of the handed worktree (`pre-existing/missing` and `exception-declared` need no path); and a `failing-check quality` line. On Codex, whose hook cannot continue a child, the `blocked` route is the first route. Every malformed report is recorded `oso.verdict_shape=malformed` and the retries count within the attempt, never as new attempts. Degrade: when the seam knows no worktree or ref, the path check is skipped and `verdict-path-check-skipped` is logged. The 2026-09-01 `failing-check evidence-chain` line, on an empty diff, is invalid here.
- C2-D5 (new): `oso.probes_executed` is counted from the host's own tool log for the child — OpenCode `tool.execute.after` per child session; Claude and Codex from the agent transcript's tool-use records where the host gives a path; `null` otherwise — and recorded beside `oso.probes`. `oso report` prints claimed against executed and lists `evidence-not-executed` per verdict where claimed exceeds executed. A reading, never a block: C5-D1(d) decides whether it becomes one.
- C2-D6 (new): the `verify_green` receipt. `oso-state set … verify_green=true` refuses — exit non-zero, the record's line printed — when the sidecar's newest verifier record for (this change, this `active_slice`) carries `oso.verdict ≠ pass` or `oso.verdict_shape = malformed`. The write in `/plan` §6 step 4, the wave's green window and `/debug` §5 keep their wording: the gate is silent when it agrees. The never-commit-over-FAIL rule stops being a rule the orchestrator remembers and becomes a refusal it meets.
- C2-D7: `oso report [<change> | --all] [--json]`: first-fail rate, rounds per slice, verdicts by role and by model, findings by tier, `criteria.asked` vs `answered`, claims confirmed/refuted, probes claimed vs executed, malformed verdicts, unreceipted greens, launch outcomes, escalations. - C2-D8: the write is measured: ≤ 5 ms per append in `core/test/perf/verdicts.test.ts`; the validator ≤ 20 ms including the `git diff --name-only`; the handoff gate's own latency test keeps its bound.

## 6. Risks and their treatment

| Risk | Treatment |
|---|---|
| `proof:` becomes theatre — probes written, not run | C1-D4: the verifier re-runs and refutes; C2-D5 counts executed probes against claimed ones; a refuted claim fails the slice and is counted |
| The verifier anchors on the applier's claims | C1-D4: own probing first, claims second, the `proof:` block only and never the narrative |
| The applier contract grows back into prose | G2; the rewrite's C5 preamble bound test covers the agents; C1-S1's verify counts the contract's rule sentences and must not exceed today's |
| The validator rejects a legitimate verdict | every refusal names the line; the relaunch carries it; C2-S1's fixtures include every shape the two contracts define; `exception-declared` and `pre-existing/missing` need no path, so a docs-only slice with its exception is never rejected |
| The `verify_green` refusal blocks a legitimate green | it refuses only over a RECORDED `fail` or a malformed shape for the same slice — the verifier's own word — and allows with an event where no record exists |
| A host's SubagentStop input differs from its documentation at C2-S2's §2 | C2-D2 reads whichever of `last_assistant_message` and the agent transcript the host actually delivers; if neither, that host's capture degrades to `oso.verdict_shape=none` with an event and the divergence is recorded — the other seams stand |
| The same-child retry loops a weak model on the same malformed line | bounded at two per host, then the `blocked` route; the host's own eight-block cap stands above it on Claude; every retry is recorded |
| The `permission.ask` hook is absent or shapeless on the pinned host | C0-D5(a)'s config rows carry the harness paths alone; `git commit` and `doom_loop` stay the operator's prompts; `oso profile show` prints them; the divergence is recorded, never worked around |
| The closed tool surface denies a tool a judge needed | each block is rendered from the Claude twin's list, which is what that judge has on Claude today; a judge that needs more on OpenCode than on Claude is a parity finding, recorded, not a wider block |
| OpenCode `oso_launch` drifts from `oso_wave` | one module, the wave runner with `children.length === 1`; one test suite |
| A telemetry write or a validator slows a Stop, a SubagentStop or a launch | append-only, ≤ 5 ms measured; validator ≤ 20 ms measured (C2-D8); never blocks (G2) |
| Profile or posture rows clobber an operator's `opencode.json` | leaf merge of owned keys only (parity D24); `oso verify` asserts the rest untouched |
| A foreign approval trusted from a file | G10: only through the resuming host's own grant; the artifact carries digest, host and date and is never edited |
| Before/after not comparable | `oso report` groups by project, host and model; the target is read on the same project where possible and stated as directional otherwise (G5) |
| The C-class (orchestrator payload) survives C1-D5 | measured by C2; if it stays ≥ 10 %, the presence phase queues a generated-payload change, not this roadmap |
| A cheap orchestrator still skips a discipline rule (journal, separate state writes) | the record is the seam's, not the orchestrator's (C2); the green needs the seam's receipt (C2-D6); the plan's tokens are checked at the grant (C1-D7) — what the orchestrator forgets, the harness holds |

## 8. Glossary of the numbers a verifier reads

- **First-fail rate**: slices whose FIRST verdict is `fail` ÷ slices with a first verdict, over a stated window; C2's `oso report` computes it from `oso.attempt = 1` records; before C2 it is counted from the journal's first `verifier verdict` line per slice, or from the OpenCode store's first verifier session per slice.
- **≈ 40 % baseline (Claude)**: 63 FAIL verdicts over rounds and ≈ 45 first-PASS across 14 journals on 2026-08-28; ≈ 32 distinct slices failed at least once.
- **3 of 8 baseline (OpenCode, cheap models)**: three runs read from the store on 2026-09-01; 12 verdicts, 4 FAIL; the bcs-mpa-core run was documentation-only with a `grep` / `sqlcmd` bar, which is why it reads 1 of 6.
- **Class A–F**: the six root-cause categories of engram `oso/applier-fail-diagnosis`.
- **"≥ 20 slices"**: the window for every target and threshold — fewer slices is "not enough data", recorded as such, never a pass.
- **"≤ 5 ms" / "≤ 20 ms"**: mean of 100 runs in `core/test/perf/`, locally and on the PR runner.
- **"Probes"**: `cmd:` lines under `evidence:` in a verifier verdict. **"Probes executed"**: tool calls the host logged for that child session.
- **"Valid" verdict**: the C2-D4 shape. **"Malformed"**: any report the validator refused, with the line it named.
- **"Unreceipted green"**: a `verify_green=true` written with no verifier record for its slice — expected on `/quick`, the sweep and a design audit; anything else is a reading for C5.
- **"Green"**: exit 0, ≥ 1 test executed, zero skipped tests without a nightly/certify guard (as the rewrite defines it).
- **"Prompt-free"**: zero `permission requested` lines in a headless child stream for the operations C0-D5 names; every other prompt is one `oso profile show` lists.
