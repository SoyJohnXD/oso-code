# OpenCode parity

Release ledger for the third host, required by ADR-0097 as extended by ADR-0151. It records what Claude Code and OpenCode do not share, why, and the assurance left after each adapter's mitigation. The neutral body under `plugin/skills/_shared/bodies/` states a rule that is true on all hosts; the file under `plugin/skills/_shared/platform/<host>/` states how that host spells it. A rule written once and carried without a capability or assurance difference never appears here.

## How to read this file

- **Verified** — both hosts have an answer confirmed against a pinned OpenCode binary and a live probe (ADR-0151), or proven by the slice that closed it. A row names the binary its evidence was taken on wherever that is not the current pin.
- **The pin** — OpenCode 1.18.22, the version `SUPPORTED_OPENCODE_VERSION` in `bootstrap/install-opencode.sh` carries and the one every bar resolves its binary against. It reached that number in two moves inside 0.27.0, each on measurement rather than assumption. From 1.18.18 to 1.18.20: `tests/opencode-contract-bar.sh` and `tests/opencode-behavior-bar.sh` were run against 1.18.18, 1.18.20 and 1.18.21 and returned the same check names with the same values on all three. From 1.18.20 to the pin above: both bars were run again against 1.18.20 and 1.18.22 and returned the same check names with the same values on both — the contract battery at 67 passed / 0 failed on each, differing on one line only, the check whose value IS the pin, and the behavior battery at 11 passed / 0 failed on each. So the host contract this ledger rests on is the same contract at the new pin. What those two bars cover is what each move re-measured, and nothing wider: a row naming 1.18.18 or 1.18.20 was measured on that binary and keeps it, because moving the label would be rewriting evidence rather than a version. Two decisions rest on 1.18.20 behaviour the bars do not reach and were not re-measured here — ADR-0155, that a `variant:` declared with no `model` beside it is dropped when the host reads the agent, and ADR-0156, that a headless child can be auto-refused `external_directory` permission for the very worktree it was pinned to.
- **No package counterpart** — OpenCode can provide the behavior only through installer-owned user surfaces, not through the plugin package itself.

Unknown host facts block a release claim; this document does not ship placeholders. The port is complete: the 16 slices of the opencode-parity plan (S1–S16) closed 2026-08-19, and every row below is verified and names the slice or decision that closed it. The six rows the skeleton left pending all resolved with their slices and appear in the table below. Baseline: the pin above, first taken at 1.18.18 (ADR-0151, 2026-08-18).

## Where the shared tree has to land

The OpenCode wrappers under `opencode/skills/<skill>/SKILL.md` reference `../_shared/…`, which resolves inside the installed config root. The installer copies `plugin/skills/_shared/` beside the nine wrappers under `~/.config/opencode/skill/` (D11), so the tracked `opencode/` tree is distribution input, never a claim that raw `opencode/` alone is complete — the same property the Codex marketplace assembles under its own root.

Every release that touches any of the three host trees reviews this ledger under ADR-0097, alongside the Claude and Codex ledgers it shares the obligation with. "No change" is a valid review result; leaving a known loss, a changed host cap or a future-tense verification claim unexamined is not.
