# Codex parity

Release ledger required by ADR-0097. It records what Claude Code and Codex do not share, why, and the assurance left after each adapter's mitigation. The neutral body under `plugin/skills/_shared/bodies/` states a rule that is true on both hosts; the file under `plugin/skills/_shared/platform/<host>/` states how that host spells it. A rule written once and carried without a capability or assurance difference never appears here.

## How to read this file

- **Settled** — both hosts have a verified answer and the relevant platform files carry it.
- **Degraded** — the Codex adapter preserves the workflow with a narrower capability or assurance, stated after its mitigation.
- **No package counterpart** — Codex can provide the behavior only through installer-owned user surfaces, not through the plugin package itself.

An unknown host fact blocks a release claim; this document does not ship placeholders. Release 0.18.0 is verified against the Codex 0.146.0 floor in ADR-0094.

## Frozen loss and degradation ledger

These seven entries are release requirements, not a summary inferred from the divergence table. A mitigation stays beside the boundary it cannot remove.

| Loss or degradation | Codex mitigation | Boundary that remains |
|---|---|---|
| Plan approval composes native UI with a narrower local rail | `Stop` binds the delivered document and persists its artifacts, `UserPromptSubmit` consumes native `Implement the plan.` only for the matching pending digest, and pending `PreToolUse` denies new local tool calls | Hosted tools, specialized paths and `write_stdin` on an existing process do not cross that hook. The flow closes its processes and routes no execution writes through those surfaces, but the hook coverage remains narrower |
| Oso voice is global instruction prose instead of an applied output style | The installer owns one bounded Oso block in `~/.codex/AGENTS.md` | Context compaction may weaken it; Claude Code's applied output style has the stronger host-level placement |
| Security review uses a different native reviewer | The dedicated security subagent runs `codex review` with a security-only instruction and reports its exact covered scope | It is not Anthropic's native `security-review` skill; the review engine and report semantics are Codex's |
| Two agent sessions in one repository share one state file | Repository keying keeps the main checkout and every linked worktree on the same commit and edit gates | Session isolation is deliberately lost; the last writer owns the file's `session` field and teardown |
| The authenticated integrator smoke runs outside CI | `bootstrap/verify-codex.sh` always reaches a `passed:` summary and runs the real delegation when Codex authentication is available | CI sets the explicit `OSO_VERIFY_SKIP_SMOKE` boundary; authenticated release evidence requires an operator-run local release check |
| A roadmap runs ASSISTED here, never unattended | `$oso-code:roadmap` chains the queue: one planning exchange, one global decision ledger, one approval for the roadmap, the autonomy policy answering what surfaces mid-child and queuing for the end what it cannot — a child that queuing sets aside included — and the presence phase at the end are all the same as on Claude, and the queue advances from one child to the next without the operator arranging it | Each child still stops at this host's plan approval rail, which passes only on the byte-exact operator prompt in the approval-gate row above — a prompt no model may produce on the operator's behalf, since a harness that types its own approval has approved nothing. The operator decides once and is present once per child; they cannot walk away from the run |
| The oso permission profile is the machine default because Codex has no per-project profile selection (ADR-0122) | The extended secret denylist, `.git/config` = `"read"`, and the metadata-IMDS denies from ADR-0121 apply to every session regardless of relatedness | Any Codex session on this machine, not only oso-code work, can write under `.git` outside `.git/config`, and can reach every repository's `oso-state` flags, plan documents and install-backup snapshots under the shared state root |

## Where the shared tree has to land

The Codex wrappers under `codex/skills/<skill>/SKILL.md` reference `../_shared/…`, which resolves inside the installed plugin's skills root. The installer assembles a private marketplace under `~/.local/share/oso-code/codex-marketplace`, copies `plugin/skills/_shared/` beside the nine wrappers, and registers that self-contained root. The tracked marketplace template is therefore distribution input, never a claim that raw `codex/` alone is complete.

Every release that touches either host tree reviews this ledger under ADR-0097. “No change” is a valid review result; leaving a known loss, a changed host cap or a future-tense verification claim unexamined is not.
