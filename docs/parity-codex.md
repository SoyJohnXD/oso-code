# Codex parity

Release ledger required by ADR-0097. It records what Claude Code and Codex do not share, why, and the assurance left after each adapter's mitigation. The neutral body under `plugin/skills/_shared/bodies/` states a rule that is true on both hosts; the file under `plugin/skills/_shared/platform/<host>/` states how that host spells it. A rule written once and carried without a capability or assurance difference never appears here.

## How to read this file

- **Settled** — both hosts have a verified answer and the relevant platform files carry it.
- **Degraded** — the Codex adapter preserves the workflow with a narrower capability or assurance, stated after its mitigation.
- **No package counterpart** — Codex can provide the behavior only through installer-owned user surfaces, not through the plugin package itself.

An unknown host fact blocks a release claim; this document does not ship placeholders. Release 0.18.0 is verified against the Codex 0.146.0 floor in ADR-0094.

## The divergences

| Block | Claude Code | Codex | Status |
|---|---|---|---|
| Shared-file paths | `${CLAUDE_SKILL_DIR}/../_shared/<file>.md` | `../_shared/<file>.md`, resolved against the directory holding the `SKILL.md` — the rule Codex states for every relative path a skill writes | Settled |
| Question rounds | `AskUserQuestion`, 4 per round (its platform cap) | `request_user_input`, Plan-Mode only, with a schema maximum of 3 questions; the Codex binding holds decision rounds to 3 per round and carries a fourth question into the next round | Settled — different host caps |
| The approval gate | `ExitPlanMode`, whose native UI renders and enforces approval of the plan document | Native Plan Mode keeps phases 1–5 read-only. A `Stop` hook binds the wire-exact repaso-first message to pending state; after the operator toggles Plan Mode off, `UserPromptSubmit` accepts only the whole case-sensitive prompt `APPROVE OSO PLAN` from the same session and atomically marks that digest approved. While pending, the catch-all `PreToolUse` hook denies every new local function-tool call; same-session `CANCEL OSO PLAN` is the host-side abandonment path because that deny also blocks model-invoked state cleanup. This is hard enforcement for local tools, not Codex's native approval UI: hosted tools, specialized paths and `write_stdin` for an existing process do not cross that hook, so the harness closes live exec sessions before presentation and routes no execution writes through hosted tools | Degraded — equivalent local rail, narrower hook coverage |
| Making a launch wait | `run_in_background: false` on the launch (client v2.1.198+) | Codex wait operation plus a repo/agent-keyed receipt published by the host-side `SubagentStop` hook. The caller knows the unique agent id returned by spawn; the hook session id is metadata, never an identity the model has to discover. The receipt is atomic, attempt-scoped, bounded and consumed once; it proves message completion but carries no verdict. The returned message remains the only source of pass/fail/blocked/done/findings | Settled |
| The delivery rule | The TUI drops assistant text preceding a same-turn tool call, so operator-facing content ends the turn | The adapter claims nothing about same-turn preservation and depends on none: operator-facing content ends the turn, and a tool call starts a later turn | Settled — the conservative policy is host-independent; same-turn preservation is outside the contract |
| Invoking a non-forked skill | The Skill tool, under the `oso-code:<name>` plugin namespace | Installed plugin skills surface under the same `oso-code:<name>` identity; operator modes are `$oso-code:plan`, `$oso-code:quick`, and `$oso-code:debug`. An orchestrator opens and reads an auxiliary skill's installed `SKILL.md`; forked judges are the explicit exception in the next row | Settled |
| A forked judge | `context: fork` in the skill's own frontmatter | Four dedicated custom roles pin `gpt-5.5` at `xhigh`. The three non-security judges are read-only; `oso-security-reviewer` is the D7 exception, with an outer `danger-full-access` role only to launch the networked authenticated CLI and a nested review constrained back to `workspace-write` as detailed in the native-security row. The caller passes the absolute Codex wrapper path and invocation arguments; the fresh subagent reads the wrapper plus its neutral and Codex-platform bindings itself. S6's handshake, tracked in its own row, still governs when a result may be consumed | Settled |
| The explorer | The built-in `Explore` agent | Codex 0.146's built-in `explorer` role, inheriting the parent Plan Mode's read-only permission; it is native and therefore not an eighth oso-code TOML | Settled |
| The integrator's git authority | The agent's Bash tool reaches the main checkout, linked worktrees and git metadata under the host's existing permission model | Codex `workspace-write` protects `.git`, its resolved gitdir and paths outside the active workspace. The merge-only `oso-integrator` role therefore declares `danger-full-access`; its narrow contract still forbids source edits, conflict resolution, history rewrites, force and push. Applier and verifier remain `workspace-write`. A live parent permission override can supersede a role default, so `bootstrap/verify-codex.sh` runs an authenticated integrator smoke that observes the delegated role merge, worktree removal and branch cleanup instead of trusting this field alone | Settled — broader sandbox, narrower role contract |
| The state command | `"${OSO_STATE_BIN:-oso-state}" --session "${CLAUDE_CODE_SESSION_ID}" <verb>` | The installer publishes `OSO_STATE_BIN` and the fixed `OSO_AGENT=1` marker through `shell_environment_policy.set` for tool subprocesses, and prefixes installed user-hook commands with `OSO_AGENT=1` because Codex 0.146 does not apply that shell policy to its separate hook runner. Model-issued state calls use `--session "${OSO_AGENT}"`. Repository identity remains host-neutral (ADR-0095). Approval and handoff hooks retain the real payload session id where same-session isolation is part of their contract | Settled — fixed Codex agent marker, real hook identity where required |
| User configuration ownership | Claude's plugin owns its packaged payload; bootstrap additions outside it are bounded independently | Codex bootstrap owns one primary `config.toml` region and, inside the host-shared `[features]` table, only the leaf block containing `hooks` and `multi_agent` (ADR-0098). Unrelated current and future feature keys remain operator-owned; a pre-existing oso-owned leaf outside the block is rejected before mutation instead of silently adopted | Settled — leaf-level ownership in a shared host table |
| The runtime gates | This plugin's own hooks — a `PreToolUse` matcher and a git `pre-commit` hook. The matcher arms on the session its payload names; the git hook arms on `CLAUDE_CODE_SESSION_ID` in its environment (ADR-0095) | **A Codex plugin cannot safely self-trust hooks (ledger D9).** The installer verifies published source-integrity hashes, writes the user manifest and handlers outside the plugin, and wires the git hook only when no other owner exists; ADR-0099 additionally permits migration of the exact single-hook oso-code checkout path, never a lookalike or mixed owner. The operator must review and trust the user hooks through `/hooks`; no `trusted_hash` is synthesized from a different hash contract | No package counterpart — installed user rail requires explicit trust |
| The worktree root | `~/.local/state/oso-code/worktrees/<sanitized session>/<slice>` | `$HOME/.local/state/oso-code/worktrees/${OSO_AGENT}/<slice>`. The installed `oso` permission profile adds the parent as a workspace root, while every delegated payload still carries its exact worktree path and base ref | Settled — shared fixed marker and explicit permission root |
| The session teardown | The `SessionEnd` hook, which reads `repo_path` | Same hooks constraint as the gates row | No package counterpart |
| The native security reviewer | Anthropic's `security-review` skill, invoked through the Skill tool inside the fork | The dedicated `oso-security-reviewer` subagent invokes `codex review` itself with a native target selector and security-only developer instructions. Its outer `danger-full-access` role is the narrow exception to read-only judges because a nested authenticated CLI needs network and writes runtime state outside the workspace; the inner review returns to `workspace-write`, enables network, disables interactive approval and pins the review model. The exact report header records whether it covered staged/unstaged/untracked changes alone or the validated base range plus that pending surface | Settled — native review remains inside the dedicated subagent |
| The Impeccable design bar | `impeccable:impeccable` through the Skill tool; its installed-plugin numeral comes from `claude plugin list`, and absence points to the two Claude marketplace commands | A provider-correct `.agents` build is copied into `~/.agents/skills/impeccable`, never linked to or executed from its source tree. The harness reads that mounted `SKILL.md` completely and supplies the exact argument represented publicly as `$impeccable init`, `$impeccable document` or `$impeccable audit <touched surfaces>`; appliers receive only absolute paths below the mounted root. The installed-skill numeral comes from its `version:` field, findings take the Codex subagent handoff, and absence points back to `install-codex.sh`. The mount rejects the superficially similar Claude-compiled build because its `.claude` paths and slash commands are dead on this host | Settled — same design bar, provider-specific skill build and invocation |
| Reaching deferred tools | `ToolSearch` loads the fallow tools into the fork | Every configured MCP tool is already listed under its server-prefixed name; absence from the listing IS the unavailability evidence | Settled |
| Linting what a host file SAYS | The four rules that read a skill's bound text — 3, 4, 6 and 8 in `tests/plugin-lint.sh` — collect the Claude wrapper, neutral body and `platform/claude/` through `skill_sources` | The same rules collect the Codex wrapper, neutral body and `platform/codex/`; call-site discovery recognizes the plugin-scoped backticked `oso-code:<name>` identity that Codex 0.146 reports for bundled skills. Mutation cases put a remote-qualified acquisition and a vocabulary-free namespaced invocation in the Codex tree and require the exact host-aware lint failures | Settled |

## Frozen loss and degradation ledger

These five entries are release requirements, not a summary inferred from the divergence table. A mitigation stays beside the boundary it cannot remove.

| Loss or degradation | Codex mitigation | Boundary that remains |
|---|---|---|
| Plan approval is not Codex's native approval UI | `Stop` binds the delivered document, `UserPromptSubmit` consumes one exact token, and pending `PreToolUse` denies new local tool calls | Hosted tools, specialized paths and `write_stdin` on an existing process do not cross that hook. The flow closes its processes and routes no execution writes through those surfaces, but the hook coverage remains narrower |
| Oso voice is global instruction prose instead of an applied output style | The installer owns one bounded Oso block in `~/.codex/AGENTS.md` | Context compaction may weaken it; Claude Code's applied output style has the stronger host-level placement |
| Security review uses a different native reviewer | The dedicated security subagent runs `codex review` with a security-only instruction and reports its exact covered scope | It is not Anthropic's native `security-review` skill; the review engine and report semantics are Codex's |
| Two agent sessions in one repository share one state file | Repository keying keeps the main checkout and every linked worktree on the same commit and edit gates | Session isolation is deliberately lost; the last writer owns the file's `session` field and teardown |
| The authenticated integrator smoke runs outside CI | `bootstrap/verify-codex.sh` always reaches a `passed:` summary and runs the real delegation when Codex authentication is available | CI sets the explicit `OSO_VERIFY_SKIP_SMOKE` boundary; authenticated release evidence requires an operator-run local release check |

## Where the shared tree has to land

The Codex wrappers under `codex/skills/<skill>/SKILL.md` reference `../_shared/…`, which resolves inside the installed plugin's skills root. The installer assembles a private marketplace under `~/.local/share/oso-code/codex-marketplace`, copies `plugin/skills/_shared/` beside the eight wrappers, and registers that self-contained root. The tracked marketplace template is therefore distribution input, never a claim that raw `codex/` alone is complete.

Every release that touches either host tree reviews this ledger under ADR-0097. “No change” is a valid review result; leaving a known loss, a changed host cap or a future-tense verification claim unexamined is not.
