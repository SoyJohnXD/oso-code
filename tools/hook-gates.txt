# The gates, once, for every host the harness runs on. tools/render-hooks-json.sh
# turns this table into each host's hooks.json; tests/plugin-lint.sh's
# check_hook_renders_and_published_hashes_match fails when a committed manifest is
# not what it renders. Nothing here is written twice: the matcher a host spells
# for a gate is a cell in this file and nowhere else.
#
# Three record kinds, each labelled by its first field, each ending in ONE CELL PER
# HOST in the order the `host` rows appear:
#
#   host <name> <manifest, relative to the repo root> <command root>
#   gate <id> <event> <script under the hooks directory> <wired|none per host>
#   tool <gate id> <the name that host spells the tool with, or none, per host>
#        <read|write|role> <yes|no>
#
# A tool row's last two cells are the capability model, independent of how many
# hosts precede them: whether the name READS or WRITES — the class that decides
# whether a tool could ever belong behind the `edits` gate at all, since only a
# tool that can mutate repository files earns that gate rather than the
# `unknown` catch-all alone — and whether the name is MANDATED by a protocol
# this harness itself installs and instructs the model to follow, which is what
# made mem_judge's absence a deadlock rather than an inconvenience (5905a27). A
# `handoff` row names a subagent role rather than an invocable tool, so `role`
# answers its class instead of read or write; its mandated cell is still real —
# the harness's own delegation protocol requires exactly these eight role
# identifiers. Nothing here is a second copy of the renderer's own answer:
# render() below never reads past each row's per-host cells, so these two never
# change a byte of what renders (the same tests/plugin-lint.sh rule asserts the
# committed manifests are still exactly that render).
#
# `none` is an answer, not an omission — the host has no counterpart. A row that
# leaves a host unanswered is refused. Runtime default-deny is separate and real:
# the Codex-only `unknown` gate renders a final `.*` matcher and its tool rows are
# the exact allowlist passed to block-unknown-tool.sh. Specific Bash/apply_patch
# gates still make their own state verdict; the catch-all only rejects a tool name
# absent here, and only after an oso-code state exists for the repository.
#
# The command root is quoted so a path with spaces survives the shell each host
# runs the command through. Claude Code interpolates ${CLAUDE_PLUGIN_ROOT} itself;
# Codex has no such variable and its hooks are user-level rather than bundled, so
# the installer that places them substitutes __OSO_HOOKS_DIR__ for the absolute
# directory it wrote them to. The renderer also prefixes every
# Codex command with `OSO_AGENT=1`: Codex 0.146 does not pass its tool-command
# shell_environment_policy into the separate user-hook command runner.

host  claude  plugin/hooks/hooks.json  "${CLAUDE_PLUGIN_ROOT}"/hooks
host  codex   codex/hooks/hooks.json   "__OSO_HOOKS_DIR__"

# Row order is render order, and on Codex render order is TRUST order: `[hooks.state]`
# keys each trusted hash by position (`<hooks.json>:<event>:<group>:<handler>`), so
# inserting or reordering a row shifts the later groups of that event.
#
# persist-state-bin.sh is Claude-only because its whole mechanism is CLAUDE_ENV_FILE,
# which no other host writes; Codex user hooks get no shell_environment_policy at all,
# so a Codex-wired handler resolves oso-state from the runtime sibling of its own
# hooks directory instead. Wiring it there would cost a trusted position and do nothing.
#
# warn-stale-version.sh is Claude-only for the same reason read the other way: it
# compares an install against the marketplace that served it, and Codex has no
# marketplace — bootstrap/install-codex.sh copies a clone's files to a runtime
# directory, which the `claude plugin` commands its message names cannot reach. A
# Codex-wired handler would either never speak or tell an operator to update an
# install that came from somewhere else.
#
# A PreToolUse gate's script declares its own way out or it does not land here:
# a `# Recovery:` header line naming the operator's legitimate next step, or
# explicitly stating there is none — never a cause the operator has to
# translate into an action themselves, and never the state write that would
# disarm the gate it belongs to. tools/render-hooks-json.sh's own parser
# enforces this the same way it already enforces a matcher or a script's
# existence: closed, before any render, check or classify mode runs. Stop and
# UserPromptSubmit gates block through a different channel (`stop_block`,
# `control_block`) this rule does not reach yet.

gate  commit    PreToolUse    block-commit-until-green.sh   wired  wired
gate  edits     PreToolUse    block-edits-without-slice.sh  wired  wired
gate  unknown   PreToolUse    block-unknown-tool.sh          none   wired
gate  handoff   SubagentStop  publish-subagent-handoff.sh    none   wired
gate  planstop  Stop          capture-plan-approval.sh       none   wired
gate  autocontinue Stop       auto-continue.sh              wired  none
gate  planprompt UserPromptSubmit approve-plan-token.sh       none   wired
gate  statebin  SessionStart  persist-state-bin.sh          wired  none
gate  stale     SessionStart  warn-stale-state.sh           wired  wired
gate  version   SessionStart  warn-stale-version.sh         wired  none
gate  teardown  SessionEnd    cleanup-state.sh              wired  wired
gate  proddeploy PreToolUse   block-prod-deploy.sh          wired  wired
gate  reanchor  SessionStart  reanchor-after-compact.sh     wired  none
