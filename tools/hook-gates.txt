# The gates, once, for every host the harness runs on. tools/render-hooks-json.sh
# turns this table into each host's hooks.json; tests/plugin-lint.sh rule 13 fails
# when a committed manifest is not what it renders. Nothing here is written twice:
# the matcher a host spells for a gate is a cell in this file and nowhere else.
#
# Three record kinds, each labelled by its first field, each ending in ONE CELL PER
# HOST in the order the `host` rows appear:
#
#   host <name> <manifest, relative to the repo root> <command root>
#   gate <id> <event> <script under the hooks directory> <wired|none per host>
#   tool <gate id> <the name that host spells the tool with, or none, per host>
#
# `none` is an answer, not an omission — the host has no counterpart. A row that
# leaves a host unanswered is refused. Runtime default-deny is separate and real:
# the Codex-only `unknown` gate renders a final `.*` matcher and its tool rows are
# the exact allowlist passed to block-unknown-tool.sh. Specific Bash/apply_patch
# gates still make their own state verdict; the catch-all only rejects a tool name
# absent here, and only after an oso-code state exists for the repository.
#
# The command root is quoted so a path with spaces survives the shell each host
# runs the command through. Claude Code interpolates ${CLAUDE_PLUGIN_ROOT} itself;
# Codex has no such variable and its hooks are user-level rather than bundled
# (ADR-0094), so the installer that places them substitutes __OSO_HOOKS_DIR__ for
# the absolute directory it wrote them to. The renderer also prefixes every
# Codex command with `OSO_AGENT=1`: Codex 0.146 does not pass its tool-command
# shell_environment_policy into the separate user-hook command runner.

host  claude  plugin/hooks/hooks.json  "${CLAUDE_PLUGIN_ROOT}"/hooks
host  codex   codex/hooks/hooks.json   "__OSO_HOOKS_DIR__"

# Row order is render order, and on Codex render order is TRUST order: `[hooks.state]`
# keys each trusted hash by position (`<hooks.json>:<event>:<group>:<handler>`), so
# inserting or reordering a row shifts the later groups of that event.
#
# persist-state-bin.sh is Claude-only because its whole mechanism is CLAUDE_ENV_FILE,
# which no other host writes; Codex user hooks get no shell_environment_policy at all,
# so a Codex-wired handler resolves oso-state from the runtime sibling of its own
# hooks directory instead. Wiring it there would cost a trusted position and do nothing.

gate  commit    PreToolUse    block-commit-until-green.sh   wired  wired
gate  edits     PreToolUse    block-edits-without-slice.sh  wired  wired
gate  unknown   PreToolUse    block-unknown-tool.sh          none   wired
gate  handoff   SubagentStop  publish-subagent-handoff.sh    none   wired
gate  planstop  Stop          capture-plan-approval.sh       none   wired
gate  planprompt UserPromptSubmit approve-plan-token.sh       none   wired
gate  statebin  SessionStart  persist-state-bin.sh          wired  none
gate  stale     SessionStart  warn-stale-state.sh           wired  wired
gate  teardown  SessionEnd    cleanup-state.sh              wired  wired
