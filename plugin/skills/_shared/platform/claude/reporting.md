# Milestone reporting — Claude Code

## The native card is not the report

Launching a delegation through the Agent tool, or forking a judge through the Skill tool, draws this client's own native subagent card — a UI element the harness does not control and cannot suppress. That card shows only THAT something ran; it carries no role name the operator recognizes, no assignment, no tree, and no verdict. The milestone text `../../reporting.md` requires is never skipped because a card is already on screen, and it is never folded into the card's own caption — it is separate operator-facing content, delivered exactly as every other one on this host: ending the turn as plain text, with the tool call in a later turn. One class of run reads that last clause the other way, and the section below is where this host states it.

## The unattended run — the carve-out, and the record that pays for it

An UNATTENDED RUN is this repository's runtime state carrying `auto=running` for this session: the marker the AUTO disposition arms (`bodies/plan.md`'s ground rules) and the ROADMAP chain arms per child (`bodies/roadmap.md` §4). While it stands, operator-facing MILESTONE text does NOT end the turn — it rides the stream as the work happens and the next tool call follows it in the same turn — because a run that ended its turn at every milestone stops at every milestone, with nobody there to say "continue", which is the stall this carve-out exists to end. The rule above is unchanged for everything else this host delivers: a question round, a plan document and an approval gate all still end the turn, and none of them belongs to a run nobody is watching.

What the carve-out costs is stated rather than denied: this TUI drops text that precedes a tool call in the same turn, so a milestone delivered this way may never reach the screen at all. That cost is ACCEPTED, because the stream was never the record. Every milestone `../../reporting.md` fires is ALSO appended full-text with `oso-state journal "<the milestone exactly as it was written>"` — one journal per change, named by the `auto_change` value the marker was armed with — and that file is what the operator reads on their return, what a compaction cannot take, and what makes a swallowed line a cosmetic loss rather than a lost report.

Two deliveries still END THE TURN under the marker, and the list is closed: the PARK, and the final report of the run THE OPERATOR ARMED — a plain-AUTO change's own close (`bodies/plan.md` §7), or a chain's own report over the whole queue it ran (`bodies/roadmap.md` §5). Each is the run handing itself back rather than a milestone going by. The close is SEQUENCED for exactly that reason — the disarm first (`auto=done`, a tool call), the report after it as the same turn's trailing text — since text that FOLLOWS a tool call is delivered where text that precedes one may not be. A roadmap CHILD's own close is NEITHER of the two, however final it reads inside that child: the chain arms the next child in the same turn, and a child ending is not among the moments allowed to interrupt an absent operator, so that close rides the stream and the journal like every milestone before it.

`auto-continue.sh` is the mechanical net behind all of it and never a substitute for it: this plugin's Stop hook reads that same `auto=running`, pushes an unattended run on when a turn ends without parking or closing it, and gives up after a fixed number of pushes that made no journal progress. A flow that leans on the net to be restarted has already stalled once per milestone and is spending that cap to do it.
