# Changelog

## 0.19.0

**Reinstall required** — Codex's installed hooks and their published trust-boundary hashes changed again, and `bootstrap/install-codex.sh`'s own transaction gained a state migration and a CLI-version precondition it did not have before. Confirm Codex already sits at `0.146.0` first (`npm install --global @openai/codex@0.146.0` if not — the installer no longer runs that upgrade itself), pull the release, run `bash bootstrap/install-codex.sh --yes`, restart Codex, and start a new thread before testing `$oso-code:plan`.

0.18.5 was cut but never published — `git tag` still reaches only `v0.18.2`, and 0.18.3 through 0.18.5 exist only as commits. Its native Plan Mode attestation work is folded into this minor rather than left standing beside it, together with the half its own commit admitted shipping without: Codex never injects `shell_environment_policy.set` into the user-hook command runner, so `${OSO_STATE_BIN:-oso-state}` resolved to nothing on `PATH` and every plan capture blocked on a sentence that named no cause. The plan hooks now fall back to the runtime sibling `$HOOK_DIR/../bin/oso-state` — the shape `publish-subagent-handoff.sh` already used — and route the previously discarded stderr into the event log.

- Codex 0.146 derives hook `permission_mode` from approval policy and therefore emits `default` during genuine native Plan turns; Oso no longer treats that field alone as collaboration-mode evidence. One exact-turn resolver instead binds the hook's `session_id`, `transcript_path` and `turn_id` to the host-generated `task_started.collaboration_mode_kind` event — rejecting foreign sessions, duplicate turn events, symlinked transcripts and unknown modes before falling back to the documented permission field — and governs plan entry, marker-bearing `Stop` capture, Plan feedback that invalidates a pending document, exact native approval after the client mode transition, and explicit cancellation. Plan capture accepts the exact marker as the final logical line when Codex `Stop` appends its own observed terminal LF, and the approval document now accounts for all five read-only planning phases plus a doubt-pass outcome.
- Every explicit delegated launch now spawns through the installed host's real `MultiAgentV2` contract: the harness had been asserting `fork_context=false`, a parameter the installed `codex-cli 0.146.0` binary rejects outright, and every one of those launches would have failed against a real host. It now sets `fork_turns="none"` and names the child through `task_name`, and `bootstrap/verify-codex.sh` gains a standing check that greps the resolved Codex binary for its own contract literals so a future host rename is caught locally instead of surviving behind assertions that only checked the harness's own prose.
- Giving feedback on a pending plan now amends it in place instead of discarding it: an ordinary Plan Mode reply appends to `current.md` under a `## Plan Mode feedback` heading and asks the model to present the delta, rather than wiping the pending state and forcing a full re-presentation for one requested change. `Implement the plan.` still binds the whole document, not only its digest — an amendment made since the plan was presented fails approval on a content comparison, so nobody can approve text they have not been shown. `CANCEL OSO PLAN` is unchanged. A second, narrower lane lets the harness itself propose a correction to a slice that has not started, on a cited file and line, authorized by one operator confirmation instead of a full return to Plan Mode.
- The state schema gained a second identity key, `plan_approval_session`, apart from the existing ownership `session`: Codex's fixed `OSO_AGENT` marker is what lets "last write wins" work as an ownership rule on a host with no per-call session id, but the same marker was also silently orphaning a pending plan's approval identity on every later model-issued write, which could leave every local tool denied for a session that had presented nothing. `bootstrap/install-codex.sh` now migrates any pre-split state file inside its own transaction: a pending plan that still names its real presenting session is backfilled with the new key, and a pending plan the ownership marker already clobbered — unrecoverable either way — is cleared instead of left standing as a repository armed forever with no session able to disarm it.
- A denied tool call, edit or commit now names what it denied — the tool, the file, or the exact command — on its own audit-log line, versioned and carrying which gate fired and on which hook event, so a denial is diagnosable from the log alone; six previously identical malformed-plan-marker messages now each name their own structural cause. Every `PreToolUse` gate hands back an executable next step naming the real binary, session, or allowed tool (or says plainly that no remedy is known) instead of a menu the operator had to translate themselves.
- `blocked` becomes a first-class verdict across every judge that can emit it, each routed to something concrete instead of a dead end; `oso-debt-sweep` and `oso-triage` move to a writable sandbox to match the project commands their own contracts already required them to run. The orchestrator now reports what it armed, launched, and closed as five short milestone facts on every host, closing the "no me dice casi nada" gap on Codex, which draws no progress card of its own.
- `bootstrap/install-codex.sh` no longer installs the Codex CLI. It refuses to run at all unless the installed binary already sits at the pinned `0.146.0`, naming `npm install --global @openai/codex@0.146.0` as the command to run first — the previous in-place upgrade ran before the install transaction began, outside anything its own rollback could ever revert. Two more integrity defects close alongside it, from an external audit: a symlinked role-file destination is removed before its replacement is written, so the installer can never write a new role's bytes through a link to an arbitrary target; and a runtime path that differs from the real one by a single unescaped regex metacharacter no longer normalizes to, and passes, the published hash it does not actually match.
- `bootstrap/restore-codex.sh` is a new, standalone operator entry point — `restore-codex.sh [--yes] [--list] [<backup-name>]` — that lists or restores any `install-backup-*` snapshot from that backup's own recorded manifest, so a backup made by an older or newer release still restores correctly. Automatic backup pruning by total size (a 300 MiB budget) stays a standing no-op until a restore has actually been exercised at least once on that machine; only `restore-codex.sh` itself can set the marker that turns pruning on, so an operator's one recovery path is never deleted before it has been proven to work.
- The Impeccable design-bar skill is now fetched at a pinned Git tag (`skill-v4.0.2`) instead of the bare, unpinned upstream repository, and the mounted skill's own version is checked against that pin after every fetch. The authenticated integrator smoke now launches Codex against a disposable `CODEX_HOME` instead of the operator's real one — the project-trust write it provokes is unconditional and un-suppressible by any flag the installed CLI exposes — closing the defect that had already left nine orphaned project tables in a real `~/.codex/config.toml`; its handoff proof now requires a spawn, a wait and a consume to agree on one Codex-assigned agent id rather than trusting a self-reported command string. `codex login status`, the smoke's own delegation, and the Engram repair's downloads are all time-bounded now, so none of the three can hang the installer indefinitely.
- The runtime allowlist table gained a capability model — a read/write/role class, and whether a name is protocol-mandated — checked locally against each locally-wired MCP server's own live tool listing, so a future missing or renamed mandated tool fails the verifier the first time it runs after the drift lands, instead of surfacing only as another live operator denial.
- The `oso` permission profile's three broad grants are narrowed regardless of when the profile applies: `.git/config` is read-only under it (closing a `core.hooksPath` redirect route), the cloud-metadata SSRF address is denied on both its IP and hostname spelling, and the secret denylist gains named per-tier env files, private-key formats and basenames, and whole credential-store directories. The profile itself stays the machine's own default (`default_permissions = "oso"`) rather than moving to a per-invocation opt-in — the installed CLI has no per-project selector to opt into, so scoping it narrower would have meant typing a flag on every single Codex launch, forever, for a margin the rest of this narrowing already covers.
- A stale-state warning at session start now names only this repository's own runtime file, never an unrelated checkout two directories over; and a wave's worktrees now cut from the commit its own previous wave actually landed rather than from the change's frozen base ref, so a wave-2+ slice depending on an earlier wave's contract runs against a tree that actually contains it.
- The record catches up: 21 new decisions (ADR-0105 through ADR-0125) take the log from 104 files to 125, `tests/plugin-lint.sh` grows from 13 rules to 20, and CI now pins `bootstrap/verify.sh` and `bootstrap/verify-codex.sh` to their exact fixture `failed:` counts (8 and 14) instead of only checking that a summary line was reached at all.

## 0.18.0

**Reinstall required** — `bootstrap/` changed, and neither host's plugin payload carries all of its installed runtime: pull the repo and re-run `bash bootstrap/install.sh` for Claude Code or `bash bootstrap/install-codex.sh` for Codex.

oso-code now ships one harness across Claude Code and Codex. The behavioral contract lives in shared mode bodies; thin platform adapters bind each host's invocation, questions, approval, tools, state and security-review route without pretending those APIs are identical. The Codex port is pinned to the fully probed `0.146.0` CLI rather than `@latest`, and the parity ledger is now a release artifact: every intentional loss or narrower guarantee is named instead of hidden behind a claim of equivalence.

- Plan, quick and debug gain Codex wrappers over the same neutral flows, with Codex-specific routes for `request_user_input` (at most three questions per round), plan approval, delegation, Impeccable and native `codex review`. Seven TOML roles carry the apply, verify, integrate and judge contracts under explicit model, reasoning and sandbox choices. Two roles deliberately need outer `danger-full-access`: the merge-only integrator must reach git metadata and external worktrees for merge/cleanup, and the security judge must launch its nested authenticated `codex review`; their semantic contracts remain narrow, while applier and verifier stay `workspace-write` and the other judges stay read-only.
- Codex's local approval rail binds the exact presented plan through `Stop`, consumes its literal token through `UserPromptSubmit`, and keeps ordinary tools closed through `PreToolUse` until approval. It is a real local technical gate, but a narrower one than Claude's native approval UI: hosted and specialized surfaces do not inherit the complete rail, and `write_stdin` against an already-running process never crosses `PreToolUse` at all.
- Runtime state is keyed by the SHA-256 of `git rev-parse --path-format=absolute --git-common-dir`, so a main checkout and its linked worktrees reach one gate. The state deliberately survives a killed session and is shared by two sessions in the same repository; that makes the rail fail closed across worktrees, but also means concurrent sessions can overwrite each other's state.
- `bootstrap/install-codex.sh` is transactional and idempotent. It pins Codex, verifies every installed hook dependency against release-published hashes, stages the skills-only Codex marketplace plugin, renders the user hook manifest, installs seven agent roles, owns a primary `config.toml` region plus a leaf-level block for `features.hooks` and `features.multi_agent`, wires context7/fallow/Engram, mounts Impeccable, and rolls every replaced artifact back on failure. The `[features]` table remains shared, so Codex preferences such as `prevent_idle_sleep` survive installation and reinstall. An exact earlier `core.hooksPath=<checkout>/plugin/git-hooks` migrates to the self-contained runtime only when no sibling entry would be lost; copied or mixed hook directories remain foreign. Codex plugins cannot bundle user hooks or agent TOMLs, so those are installer-owned artifacts and hook trust remains an explicit `/hooks` step.
- `bootstrap/purge-codex.sh` is a separate, optional migration boundary rather than an installer side effect. It backs up complete `~/.codex` and `~/.agents` roots under mode `0700`, verifies its hash manifest before removing either source, and restores without following root symlinks or overwriting an existing destination. It never installs Codex or runs `codex login`; those remain explicit operator actions.
- `bootstrap/verify-codex.sh` reports every local component and always reaches `passed: N, failed: M`: pinned CLI, plugin payload, installed hooks and hashes, all roles, managed config, MCPs, Impeccable, git gate, state round-trip and an authenticated integrator/delegation smoke. Because Codex propagates a live parent sandbox override to spawned agents, the disposable smoke parent uses the integrator's `danger-full-access` instead of narrowing the child back to `workspace-write`; success still requires an observed delegated spawn, merge, worktree removal and branch deletion inside the temporary fixture. CI syntax-checks every new shell and proves the verifier footer against a failing fixture, but it deliberately performs no login and no real `codex exec`; the authenticated smoke stays on the operator's machine.
- The design record adds the Codex baseline, repository-keyed state, host-adapter/distribution boundary and the parity-ledger contract. The blueprint and `docs/parity-codex.md` name the remaining differences: Codex uses compact global `AGENTS.md` instructions that the host may compact, `codex review` rather than Anthropic's native reviewer, user-level hooks with explicit trust, shared state between sessions in one repo, and a real smoke test that cannot be made truthful in unauthenticated CI.
- Release checks now exercise the documentation contracts behind linter rules 10–12: every ADR records where it landed, every skill citation resolves bidirectionally through `Implemented-in:`, and README plus the linter header keep the declared thirteen-rule count honest. The Claude and Codex plugin manifests advance together to `0.18.0`; neither marketplace catalog invents a duplicate version field.

## 0.17.0

**Reinstall required** — `bootstrap/` changed, and no plugin update carries it: pull the repo and re-run `bash bootstrap/install.sh`.

Execution stops being one slice at a time — a `/plan` change now chooses, on a number the slicing phase computes, between the sequential loop it has always run and a parallel one that puts each slice of a wave in its own worktree, merges the wave through an agent that judges nothing, and re-verifies the tree they add up to before the next wave arms. The slicing bar is untouched on purpose: slices are still cut vertically and the graph derived from the cut, never the other way round. The commit boundary moves with it: a commit is part of the flow in both modes, and a push and a PR are what the operator is still asked for. The hook suite grows from 338 to 380 cases, the linter from eleven rules to twelve, and the decision record from 75 numbered files to 93:

- `/plan` §4 keeps cutting the same vertical slices and then says how they run. Each slice gains a `Depends-on` field filled from a dependency graph read off the surface map rather than guessed at slicing time, and that graph carries four edge sources — a contract and its consumers, shared state, a data flow, and VERIFICATION-BAR COUPLING, the one none of the other three shows, where two slices sharing no contract, no state, no data flow and no file still cannot pass the project's bar apart (this repo is its own example: the linter binds a cited decision id to the `Implemented-in:` line that names the citing file back, so the slice writing the citation and the slice writing the decision are one edge apart however disjoint their files read). Files overlap drops to a secondary physical check, because the Files field is declared rather than measured. The graph groups into WAVES with two structural boundaries — wave 0 is the design-foundation slice alone in the main checkout, and a CONTRACT slice never shares a wave with a MIGRATE one, whose pre-delete completeness check would otherwise grep a tree its siblings' migrations have not reached — and the phase closes on one question carrying the widest wave's width, the arithmetic (a wave costs its slowest slice plus one full integration gate; §1–§5 and §7 do not parallelize at all) and a recommendation: parallel at a width of 3 or more, sequential at 2, a concurrency cap of 4 by default, and no question at all when the ledger's base ref is `none`. It sits before `ExitPlanMode` so the mode rides inside the plan the operator is already approving instead of adding a second gate.
- §6 gains the wave loop beside the sequential steps it leaves untouched. A wave arms one session-global `active_slice=wave-<n>` plus a new `repo_path` key, cuts one worktree per slice at `~/.local/state/oso-code/worktrees/<sanitized session>/<slice>` — outside every project repo, on a branch `oso/<change>/<slice>` — launches N appliers in one message and N verifiers after them, and commits each slice as it goes green. That commit needs a GREEN WINDOW, and the cost is stated rather than buried: both layers of the commit rail read one session-global `verify_green` and neither can see which worktree a commit came from (the git hook because `core.hooksPath` is an absolute path every linked worktree inherits, the matcher because it reads the command line), so the orchestrator opens the flag, commits that one slice, and closes it — three commands with nothing between them, and while they run the rail is open session-wide for any commit from any tree. No hook changed. A wave integrates only when EVERY slice is green, and failure routes by class with none borrowing another's route: a red slice loops in its own worktree while its siblings run on, a merge conflict stops the integrator and reaches the operator with the conflicted tree exactly as git left it, and a red integration returns the WHOLE WAVE as a unit — a regression check names the slice whose behaviour broke, never the slice that broke it — with the fix entering as a new slice through the normal gate. The first wave also answers what §3 could only record as a question, whether this project's bar survives being run N times at once, and a wave that degrades draws an offer to finish the rest sequentially: an offer, never a gate.
- New `oso-integrator` agent (Read and Bash only): it merges one wave's branches one at a time in the order it was handed, names every repository with `git -C`, and NEVER resolves a conflict — no `--abort`, no reset, no `-X ours` — because which side wins is a decision about the change and decisions are the operator's. It judges nothing and gets no rubric: the merged tree's bar belongs to the gate after it, an `oso-verifier` run in a SECOND verdict shape whose criteria are the project's full bar plus one `failing-check` line per slice of the wave, none omitted, each reported as `holds`, `broken-by-the-merge` or `exception-declared`. That shape deliberately carries no `failing-check quality` line: whether a check was tautological or implementation-coupled was settled at the slice's own gate, and a merge cannot turn an independent behavioral check into a tautological one. Both delegation payloads now carry a WORKTREE PATH and a BASE REF in either mode, which also gives "the diff" the verifier has judged since 0.12.0 its first definition — `git -C <worktree path> diff <base ref>`, committed slice work and uncommitted alike — and the applier skips its own self-check under parallel (`skipped: parallel`), since N project bars on one machine contend on ports, test databases, build caches and lockfiles that separate worktrees do not isolate.
- New forked `triage` skill (`context: fork`, `background: false`, `model: opus`), the fourth judge to pin opus: it answers ONE question from read-only git evidence — is this red check attributable to the change under execution, or does it predate the base ref — and ends on `Triage: attributable`, `Triage: pre-existing`, or `Triage: skipped — attribution not established`, which is never read as either answer. The wave loop invokes it before it routes a red nobody can place, because the orchestrator wrote the plan the wave is executing and is the worst available judge of whether the wave is to blame. It stops at attribution and hands back evidence rather than a diagnosis: `oso-code:debug` owns reproduce-first triage, and running that flow here would put one flow in two files. It is model-invocable, since the orchestrator reaches it through the Skill tool mid-wave, so it is a skill and not a fourth mode — `/debug` keeps `disable-model-invocation: true` and the linter rule that routes every operator-only mode is untouched — and its scope guard is prose only, recorded as such.
- Worktrees are torn down where they were made and where they were abandoned. The integrator removes them at integration, worktrees BEFORE branches — git refuses to delete a branch a standing worktree has checked out and no force overrides that — the close clears whatever a wave that never integrated left standing, and the SessionEnd hook removes the survivors of a session that never got there, plus the ones an abandoned session left behind on the existing 7-day orphan pass. Always `git worktree remove` then `git worktree prune`, never `rm -rf`: a directory deleted behind git's back stays registered and the next `git worktree add` for that slice fails on a name only git still believes in. The repo to prune in comes from the new `repo_path` state key, read through `oso-state` rather than re-parsed, and every failure — an unreachable reader, a removal git refused, a prune that could not run — is logged instead of swallowed while the state cleanup goes on regardless. `oso-state` gains an `event` verb for exactly that: a worktree creation, a merge conflict and a red integration are neither tool calls nor state writes, so nothing in the harness could record them before. No teardown forces a removal, at SessionEnd as at the close: what git refuses to remove is uncommitted work in a wave that never integrated, so the tree is left standing with that work in it and the refusal is logged. The teardown alone carries 23 of the suite's new cases, 18 of them behind the single skip line the `bash:3.2` container prints for the block where git is absent.
- The commit boundary moves, and every surface that stated the old one now states the new one. A COMMIT is part of the flow and is never asked for: §6 lands one per slice in BOTH modes — the wave path already did, and the sequential path now commits in the main checkout inside the green its own step 4 writes, which the next slice's step 1 takes back — and the close commits what the close itself landed. PUSH and PR are the two that still require the operator to ask, in `/plan` §7 step 8 and in the always-loaded `bootstrap/claude-global.md` that used to read "never commit, push, or open a PR unless asked". Per-slice commits are ON by default from this version; a project turns them off in the ledger's §3 Verification row — the row that already settles the base ref and the concurrency question, and no new store — and off there leaves sequential the only mode, since a wave is integrated from the commits its slices land. What that shift costs the close is stated rather than buried: with the change already in commits, the pending working tree holds only what the close itself landed, so the base ref `/plan` passes to `oso-code:security-pass` is what gives that review the whole change instead of a fraction of it — and a base ref of `none`, where no slice committed, is exactly the case where the pending tree IS the change. `/quick` and `/debug` have no slices and land no commit of their own; what changed for them is the boundary they state.
- The record catches up with the mechanism. 18 new decisions (ADR-0076 through ADR-0093) take the log from 75 files to 93, each naming what it amends rather than quietly restating it — ADR-0001's never-writes invariant is why the integrator exists and is still narrowed exactly once, ADR-0051's two layers are why the green window has to exist, ADR-0037's diff finally has a definition, ADR-0063's four assignment kinds are unchanged with two coordinates added to one of them — and `docs/blueprint.md` is edited where this change made it false: phases 4, 5, 6 and 7, the two Hooks bullets that describe the armed flag and the per-session state file, and the index. `tests/plugin-lint.sh` grows a twelfth rule holding the launch site of the new agent to naming the wave's worktrees, base ref and branch list, the three things the orchestrator decides and writes down nowhere else; the hook suite goes from 338 to 380 cases and from 322 to 346 under `bash:3.2`, where five skip lines now stand for the 34 that need git or jq.

## 0.16.0

**Reinstall required** — `bootstrap/` changed, and no plugin update carries it: pull the repo and re-run `bash bootstrap/install.sh`.

The third mode made whole, and the release rails under it — `/debug` shipped in 0.13.0 unreachable from the always-loaded file that routes a session into a mode, with a close whose green one of its own branches traded away; the installer read a hard `cargo` failure as success and could repoint the marketplace at a working tree nobody chose; the verifier died mid-report on any input it could not read; and the design record was a 13-entry prose log where a decision could only be found by reading all of it. The hook suite that judges the hooks grows from 313 to 338 cases, the linter that judges the prose from six rules to eleven, and the log becomes 75 numbered decisions held from both ends:

- `/debug` is reachable and its contract closes end to end: `bootstrap/claude-global.md` routes "something broke" to `/oso-code:debug`, which is the only thing that can send a session there — the model never invokes the mode on its own — and a linter rule now holds that routing for every operator-only mode. §3's named regression test gains a bounded escape (`Verify-exception: <reason>`, only where the fix touches no code the suite can execute — a Dockerfile, a CI workflow, an editor config — and never for the §1 hypothesis override, whose test is precisely what tells whether the hypothesis was true), and §4 step 2 hands `oso-verifier` all four things it reads: the fix criteria, the zero-warnings commands the diagnosis froze, the rubric path, and the frozen diagnosis itself as fix-decision context — under that name and never "as ledger", since this flow freezes none, which the agent's own contract now states where it used to assume a ledger and fail a new abstraction for the absence of one nobody handed it. `quality-pass` names its real callers, quick and debug rather than quick and plan, and reads the diagnosis's frozen commands in debug mode. And the close's debt-sweep offer is ADDITIVE to the quality pass instead of replacing it — the old wording traded away the `Quality Pass: passed` that step 4's green reads, so that branch could never go green at all — with a fix route (findings → `oso-applier` as a debt cleanup, re-judged until `Debt Sweep: clean`), a re-run of the pass over whatever cleanup landed, and `Conformance: skipped — no ledger provided` named as this flow's expected answer rather than the re-invocation trigger the same token is in `/plan`.

Harness audit (5-judge review) — hardening across the rubric, the agents, and the gates:

- Rubric gains operational anchors: soft-trigger thresholds (parameter count, function length, nesting → written justification, never mechanical gates), a countable hard blocker (an abstraction with fewer than two real callers unless a frozen ledger decision names it), file-level single-responsibility, and a stack-translation clause (idioms named in TS/JS, applied in the host language's equivalent).
- Agents rewired: `oso-applier` and `oso-verifier` carry the full rubric; context7 is wired into executable prompts (applier never-guess-a-signature contract, plan/quick decisions verified against current docs); the verifier returns a three-state verdict.
- `/plan` decision rounds close through pre-freeze gates: a battery→ledger reconciliation checklist, an assumption register, and YAGNI citations before the human freezes the ledger.
- `/quick` quality pass now covers the full rubric bar, not a reduced subset.
- Debt-sweep findings are severity-tiered.
- Hooks: wrapper-bypass fix, stale-lock recovery, `log_event` deduplication, and fd-free verify (no `fd` dependency in the verify path).
- Bootstrap: unified CLAUDE.md budget across the install block.
- Cadence precedence: one-question-at-a-time yields to a structured skill's own cadence (e.g. `/plan` decision rounds).

## 0.6.0

- `/plan` gains a Surface mapping phase between Intent and Decision rounds: up to 3 parallel `Explore` subagents build an evidence-based map of what the change touches, and the question battery is generated from that map — every question must cite the code evidence and the consequence of leaving it undecided. The decision-rounds category table is demoted from question generator to blind-spot audit floor, with a fallback to it only when exploration surfaces nothing.
- Engram recall convention: a single `oso/index` observation (one upserted row per change, `status: executing` at Slicing, `status: done` at Close) so resuming a change means searching the index first instead of guessing topic keys. Every ledger, plan, and summary save now carries a rich title (`{topic key} — {human description}`). `/quick` summaries follow the same rich-title rule but are never added to the index.

## 0.4.0

Pilot #1 findings (expense-splitter run: 10 slices, 0 false gate blocks, but three quality gaps):

- Debt-sweep is now a pure judge: it reports findings with evidence and never edits; `/plan` must invoke it through the Skill tool (forked subagent — never inline), then an `oso-applier` cleanup assignment fixes the findings, then a fresh sweep confirms. Loop until `clean`.
- Rubric: over-documentation is now an explicit debt marker — zero comments by default, JSDoc only where code cannot be self-evident (with standard description/params/returns shape), why-shaped sentences over trivial code count as WHAT comments, and JSDoc on most exports of a file is itself a violation. (Pilot produced 49 JSDoc blocks across 32 files.)
- Rubric system level: domain logic (validation, normalization, calculation) must live in the domain layer, not UI/component folders.

## 0.3.0

- `/plan` execution is now fully delegated: each slice runs through an `oso-applier` subagent (implements exactly one slice from the frozen ledger; returns a structured `blocked` report instead of ever assuming) and an `oso-verifier` subagent (fresh-context judge with no edit tools — reruns every check itself and returns a verdict with evidence). The orchestrator resolves blocked questions with the human, updates the ledger, and relaunches; it never writes code during execution. `/quick` stays inline. Closes the self-attestation gap flagged by the adversarial review (C9, partially).
