# Changelog

## 0.22.0

**Reinstall required on Codex; on Claude Code the plugin tier carries the mode and the reinstall carries one line.** The Codex side is the installer's whole: it stages `codex/skills/` and `plugin/skills/_shared` into the private marketplace it owns, it places the two hooks whose bytes moved here and verifies them against `bootstrap/hook-hashes.txt`, which moved with them, and it owns the block in `~/.codex/AGENTS.md` that gained the routing line — so run `bash bootstrap/install-codex.sh --yes`, restart Codex, and re-trust the hooks through `/hooks` before starting a thread. On Claude Code `claude plugin marketplace update oso-code && claude plugin update oso-code@oso-code` carries the mode WHOLE and usable, refresh first for the reason 0.21.0's version-notice bullet gives: the marketplace entry's source is `./plugin`, and the wrapper, the neutral body, both platform files, the two moved hooks and the output style all live inside it, while the marketplace manifest's own description arrives with the refresh. What no plugin update can carry is `bootstrap/claude-global.md` — `install.sh` merges it into a marked block in `~/.claude/CLAUDE.md`, a file no plugin payload reaches — and the one line it gained is what makes the harness OFFER roadmap when several substantial changes arrive together. So `bash bootstrap/install.sh` is what completes the release there, and until it runs the mode works when you type it and never gets suggested to you. Both crossings sit on top of two releases nobody has published: `git tag` still reaches only `v0.19.0`, so a machine coming from the newest published release also crosses 0.20.0's `bootstrap/` work and 0.21.0's Codex reinstall and owes their remedies too. This release keeps its own entry rather than folding into 0.21.0, on the test 0.20.0 already used against 0.21.0: that entry's subject is a clean-code bar, its remedy says the Claude plugin tier carries it whole, and its acceptance was a cold read-back of a rubric — none of the three is true of a fourth mode whose acceptance is the first real roadmap somebody runs.

An operator with a batch of substantial changes already decided had to decide them again one plan at a time. `/plan` asks for the intent, the decision rounds and the approval once per change, and when the batch was settled together most of those answers are the same answers: one intent approval per change, one set of rounds per change re-answering the last set, one plan approval per change, and a human standing at every gate because each of that flow's gates is written for somebody who is there. The mode below pulls the deciding forward into one sitting and then runs the queue on what that sitting recorded.

- **A fourth mode runs an ordered queue of plan changes on one approval.** `/oso-code:roadmap` on Claude Code, `$oso-code:roadmap` after native `/plan` on Codex, operator-only on both. Its exchange is three phases — the children in run order with each one's intent, a GLOBAL LEDGER whose entries name the children they bind, and each child's own decisions — and one approval then covers the planning behind that queue and the execution of every child in it. The approval names what it does not buy as plainly as what it does: a queue that changed materially after presentation goes back through the gate whole, every child still builds and delivers the Repaso-headed plan document, and a decision the policy may not take is not licensed by it. A child is a PLAN-mode change and nothing else is queued; a quick or debug child is a recorded YAGNI rather than a silent omission, because each would need answers this version settles for plan alone — what one approval covers for a mode that has no plan document to approve, and what a debug child does when no reproduction can be got without the operator. Codex ships it ASSISTED, not unattended: its approval rail passes only on the byte-exact operator prompt, which no model may produce on anyone's behalf, so the chain advances by itself and each child still stops there. That is a release loss and it went in the parity ledger rather than a footnote — along with the fact that the mode's own Plan-Mode precondition is backed by no hook at all, since the gate that reads an invocation spelling reads plan's alone.
- **A policy declared before the approval is what answers a decision after it.** An unattended chain guarantees that one surfaces rather than risking it, so what answers it is agreed to in advance instead of improvised later. Two outcomes and no third: resolved and recorded as DELEGATED naming the tier, or QUEUED for the end while the chain moves on. Three tiers, each reached only when the one above has nothing to say — the recommendation the flow's own rounds were already required to produce, then what current practice standardizes, then the simplest thing for the operator to live with — and a tier that could not justify its answer in those same terms stays silent rather than dressing a coin toss as a recommendation. The safety net is one question: does undoing this need more than an edit and a re-run in this repository? A restore, a refund, a revocation, a retraction or another person's involvement puts it over the bar, and over the bar the policy defers instead of deciding. Four things are never a tier's question at all — a push or release, a ledger amendment, an accepted security residual, a forced deletion — because each is already refused where its own flow states it.
- **Four gates of the plan flow gain an exit, and a queued decision costs one child rather than the queue.** That flow is written for an operator standing at each of its gates; with none, four of them had no reachable exit and a child would have sat at one instead of reaching an outcome a chain can act on. Where the policy can answer — the applier's blocked questions, a conformance finding whose CODE diverged, a pick among the sweep's three cap routes — it answers in the operator's place and the answer lands in that change's own ledger, which is what makes the relaunch a fresh applier over a ledger that MOVED. Where it will not, the question is queued and the change is SET ASIDE where it stands: committed slices stay committed, an applier's pending edits stay in the tree, a conflicted merge stays as git left it, and only what the stopped work armed is disarmed. The close gains a machine entry condition in debug's shape, because nobody is there to say they are happy — the last slice green and marked, or the last wave's gate passed — and it is an entry and never a permission: the push, the PR and an accepted security residual stay the operator's. Both texts that send a decision to the operator keep that instruction word for word and gain the one case that answers instead, which the operator approved before leaving.
- **The chain refuses to arm a child over a tree that is not its own.** A child is armed with what the queue recorded, run to one of the only two words the chain reads, and the next one released on either. Before every arming it reads the checkout — `git status --porcelain`, EMPTY the bar, an untracked file included, because the next child's `add -A` takes one exactly as it takes a modification — and it reads the WORKTREE ROOT beside it, because a child set aside mid-wave dirties the checkout nowhere while its survivors sit on the very paths the next child's first wave cuts, same slice numbers, no child anywhere in the name. Over a dirty tree it arms nothing further: every un-run child takes the set-aside word with its reason, the runtime key is disarmed, and it all reaches the presence phase. Discarding the work is over the policy's own irreversibility bar, forcing a removal is on its never-solo list, and committing it under either child is an attribution nobody asked for, so refusing is the only honest move left. A roadmap in flight is durable rather than remembered: its ledger and its position are engram's, and a `roadmap` runtime key that arms no gate — so a write that never landed costs recoverability and never safety — ships with the SessionEnd sweep that drops it and the SessionStart signal that names the resume route.
- **Everything the chain could not do lands in one ordered queue behind one report.** Every decision the policy would not answer, every child a decision set aside — as ONE item with the decision, not two — whatever stopped the chain along with the standing worktree only the operator can dispose of, and every child's own pendings and named residuals, closed children included. The order is a rule rather than a matter of taste, so the same inputs produce the same queue twice: what stopped the chain, then what a child waits on, then what a running child needs, then what can be read at leisure, ties broken by run order and then by the point inside the child. The report heads it and answers three things — what was decided in their absence and on what rationale, what was deferred and why, what waited for their hand. Their run stops in front of them at three moments at most: the roadmap finished, the queue is ready, the chain is blocked. A child closing is deliberately not one of them, and the reporting contract gains that disposition as a sixth milestone which reaches the session stream alone — plus the one exception the final report needs, since a queue and its residuals do not fit in three lines.
- **The record moves with it.** Five decisions — ADR-0135 (the mode and its one approval), ADR-0136 (the autonomy policy), ADR-0137 (the set-aside disposition), ADR-0138 (the chain and its tree bar) and ADR-0139 (the presence phase) — take the log from 134 files to 139, and the one retirement is named from both ends: ADR-0139 retires two clauses of ADR-0115, its five-milestone enumeration and its one-exception rule, while that decision's required facts, its length bound, its per-host platform binding and its single-definition rule all stand. `docs/blueprint.md` gains Mode 4 and moves where this change made it false — Mode 1 §3's "returns to the human" absolute, §7's close entry, the planning line's "entirely in the host's native Plan Mode" absolute, and the engram row that had every `oso/index` row going `executing` → `done` when a roadmap's own row is a parent marker that stays. README gains the mode, its per-host spelling, the roadmap in the model expectation, the resume route for a state file naming one, and the one case its first design principle now allows; its second design principle gains the same condition, because one approval on Claude Code is the transition out of Plan Mode as much as the approval and a child that entered again would owe a second one — so a child's phases 1–5 run outside that mode, read-only by the plan flow's own rule. That fact is stated once, in the Claude roadmap platform file; the plan body's first ground rule and the Claude plan platform file send a child there rather than to a gate the roadmap already passed, the front-surface pin step rests on the flow's own rule instead of the host's mode, and the parity ledger's approval-gate row records what renders and approves a child's document on each host. Both plugin manifests and both marketplace descriptions stop saying three modes; the Codex manifest's three starter prompts stay three, the maximum that spec allows. `tests/plugin-lint.sh` grows from 28 rules to 33, and `tests/hooks-test.sh` closes at 1394 cases.
- **Three things ship known-open rather than found later.** Behavioural acceptance of this mode is the operator's FIRST REAL ROADMAP RUN and nothing here stands in for it: the bar this closes at judges text and shell, never a queue of real changes carried unattended, so the acceptance is explicitly pending. One of the presence phase's three producers of operator-hand work has no mechanism — a slice DECLARED as the operator's own, where `bodies/plan.md` §4 states exactly four slice fields and none can mark one that way, so the class ships with its two working producers and the gap recorded in ADR-0139 instead of implied by a body that lists three. And `check_milestone_reporting_contract_is_complete` has a pre-existing path to a silent green, now attributed rather than merely observed: its mode loop derives an operator-only mode from frontmatter, `frontmatter()` returns empty and exits 0 when the read of line 1 fails, and the loop then `continue`s past that mode with no flag — the mechanism behind the one silent green its `debug.md` mutation case produced in roughly forty runs. `check_global_routing_names_every_operator_only_mode` shares the shape. Fixing it is its own change and it is not attempted here.

## 0.21.0

**Reinstall required** — on Codex, because the installer owns everything this release changed there: `bootstrap/install-codex.sh` copies the three rewritten agent roles out of `codex/agents/`, stages `plugin/skills/_shared` into the Codex plugin, and places the hooks it verifies against `bootstrap/hook-hashes.txt`, which moved with their bytes. Run `bash bootstrap/install-codex.sh --yes`, restart Codex, and re-trust the hooks through `/hooks` before starting a thread. On Claude Code the plugin tier carries this release whole — the marketplace entry's source is `./plugin`, and every Claude runtime artifact this release moved is inside it; outside it the `bootstrap/` scripts moved comment-only, and the rest is the Codex side, the record and the bar — so `claude plugin marketplace update oso-code && claude plugin update oso-code@oso-code`, refresh first for the reason the version-notice bullet below gives. What no host escapes is 0.20.0: it is committed and unpublished, `git tag` still reaches only `v0.19.0`, so a machine coming from the newest published release crosses that release's `bootstrap/` work as well and needs its reinstall too. 0.20.0 keeps its own entry rather than absorbing this one — its remedy and its acceptance gate are about a Windows install, and none of this is.

The harness exported a clean-code bar it did not run, and taught a notation it forbade. Its rubric banned over-documentation and then handed the exception back: an "Earned WHY" example blessing a comment that carries an external constraint the code cannot show, which a frozen ledger decision wears exactly. The applier — the agent that writes every line of code — had never been told the rule at all; its contract enumerated four of the rubric's five sections and skipped the one carrying it. The per-slice verifier's whole rubric mandate was the Hard blockers, and over-documentation lives in Debt markers, so a change executed as N slices passed N gates that structurally could not fail one for a comment. The debt sweep meant to catch the rest ran a judge → fix loop with no exit. And this repo's own shell carried 155 decision citations behind a linter rule that made the notation look like a checked contract worth copying — so an applier copied it, into a customer's TypeScript, where the ledger those tags name never existed for the reader at all.

- **The inline comment is a debt class with no exception, and the writer is told before it writes.** The rubric states it with no exceptions and in the Hard blockers' own phrase, so the judgment contract's readability-win requirement cannot spare an accurate citation; only a language's standard public-API doc form stands outside the ban, and provenance goes to the change's ledger, the PR body or the commit message. Both hosts' `oso-applier` contracts now map all five of the rubric's sections, Debt markers included, state at write time that the inline comment is not a thing the applier produces, and route decision ids and rationale to the report's `decisions_used` field, where a citation is debt however accurate it is. `/quick` binds its own writer the same way, since the orchestrator is the writer there. Read back cold — a fresh judge given the shipped rubric, eight real comment samples from that same PR and none of the reasoning behind either — the text returned seven debt, one earned and nothing unclear: the earned one a JSDoc block on a banker's-rounding helper, the doc form the rule keeps, and among the debt the vendor-API pagination comment that used to BE the rubric's own `Earned WHY` exemplar. One judgment on eight lines against a text, not a re-run of the harness over that PR.
- **The slice gate can see a comment, and the conformance axis stops rewarding one.** Both hosts' `oso-verifier` contracts fail a diff that ADDS an inline comment, beside the Hard blockers rather than in place of them, judging the added lines and leaving the rest of Debt markers to the sweep so the gate does not become the unbounded auditor. The conformance axis had the opposite problem: it called an unimplemented decision one with no trace in the diff, and a line reading `// D22` is the cheapest trace there is, while scope-creep closed the other exit. A trace is now the code that enacts a decision; a comment naming one lands in the debt section and leaves the decision unimplemented, which is what the two separate sections were for.
- **The sweep's judge → fix loop gets an exit it cannot run past.** The close said loop judge to fix until clean, and a real close took seven rounds over three hours in which rounds five through seven found nothing but the damage round five's own applier had caused. The loop now ends on a band — no blocker and no structural finding open — and a nit that survives is the named residual: recorded in the ledger and relayed to the operator verbatim under an explicit exception to the reporting contract's counts-only rule and its length bound, never dropped because the loop was allowed to end. Three rounds is the cap, and at the cap the operator picks from exactly three routes. `/debug` takes the same bar on its additive sweep, and only there: the quality-pass loop it chains into is a different judge and stays uncapped. Every surface that stated the retired condition as a live precondition moved with it, including the design audit's, which would otherwise have demanded a verdict the new bar can never produce.
- **That loop carries its own memory, and its cleanup sweeps a class inside a boundary.** Every round ran blind over the whole diff and no rule forbade re-raising, so an orchestrator hand-carried a do-not-re-raise list that grew from two items to fourteen while one clone group was dismissed three times. The re-invocation now carries the prior rounds' findings with their dispositions — the tag, never why it became one — and a dispositioned finding is named as settled instead of argued again. The handoff that runs in that loop had no payload spec at all while the judge-findings kind beside it had one, and now gains the same: findings verbatim with file, line and tier, the change-surface list, the rubric path. Its report gains a line per finding, because a file-keyed list cannot say whether finding four was fixed or skipped. And the cleanup sweeps the pattern rather than the instance, which is what made an N-site defect cost N rounds — bounded by the findings and the change surface, per pattern and never a whole-file pass, because the inverse failure is a formatter run over documents the change touched in one cell.
- **The harness stops exporting the convention it now bans.** All 156 citations are gone from every executable — the 155 this repo's shell carried, plus one more in `bootstrap/verify.bat`, whose `REM` comment no rule scanning shell for a `#` could ever have matched — and `Implemented-in:` went with them from every decision file that carried it — 63 at the moment the purge ran, which is the 61 the log already held when this release opened plus the two it wrote under the convention before retiring it, so a diff read against that opening point sees only 61 removals. The plan body's verification-bar-coupling exemplar teaches the same lesson through the rule-count relation, which couples the linter and README exactly the way the retired example coupled a skill and a decision. Markdown prose keeps its cross-references: a document citing its decision is not a comment in code. A new rule scans every executable this repo ships — the six shell sets the syntax gate parses, and the Windows entry points and awk program it cannot — in the four notations this repo writes and the three markers those languages open a comment with, and the narrowed resolve check stays, because the prose references the decision preserved would otherwise be guarded by nothing. `tests/plugin-lint.sh` grows from 22 rules to 28, and `tests/hooks-test.sh` closes at 1366 cases.
- **A session says once when its plugin is behind the published release.** The operator's machine ran 0.17.0 for five days while 0.19.0 was published and 0.20.0 prepared, so every improvement this harness shipped sat unreachable in their projects and nothing said the manual refresh was overdue. A `SessionStart` gate now reads the version from the plugin directory it launched from, requires the marketplace registered on the machine to be served from that plugin's own repository, and reads the newest release tag off the git ref advertisement under curl's own connect and total bounds, cached for a day so an offline machine tries once rather than once per start. On drift it prints one line: both versions and the two commands that close the gap. It is silent on everything else — no drift, no network, no curl, an unreadable version, a foreign marketplace, a compaction. Claude only: Codex installs from a clone into a runtime directory no `claude plugin` command reaches, so a Codex-wired handler could only print a remedy that does not apply there. README documents the marketplace refresh beside the update, because an update alone reinstalls whatever the client's stale clone already holds — which is exactly how 0.17.0 survived.
- **The record moves with it.** Five decisions — ADR-0130 (the sweep's banded, capped exit), ADR-0131 (the loop's memory and the cleanup's class sweep), ADR-0132 (citations leave executable code), ADR-0133 (the version notice) and ADR-0134 (the inline comment as a debt class, held at three layers) — take the log from 129 files to 134, and each retirement is named from both ends: ADR-0130 retires ADR-0071's until-clean clause, ADR-0133 retires ADR-0075's single-command update spelling, and the rest of both still stands. ADR-0134 retires nothing, and says so rather than implying a predecessor: no decision ever recorded the over-documentation rule or the escape hatch this one removes — the rule arrived in a `fix(quality)` commit that amended the blueprint nowhere, leaving this log nothing to extract for it, and the `Earned WHY` example rode in beside ADR-0005 without appearing among the four clauses that decision records. `docs/blueprint.md` moves where this change made it false — Mode 1 §7's close states the band, the cap and the three routes, and the Decisions preamble stops listing the retired citation field among what a decision file carries. README's debt-sweep row stops promising to judge "stray comments", a phrase that appeared in no executable here, and names the over-documentation class the rubric now states.

## 0.20.0

**Reinstall required** — `bootstrap/` changed almost everywhere, and no plugin update carries it: pull the release and re-run `bash bootstrap/install.sh` (double-click `bootstrap\install.bat` on Windows), then restart Claude Code. The run publishes two new `settings.json` `env` keys and provisions two binaries it previously only reported on, so an existing install that looks healthy is exactly the case this release is for.

0.10.0 claimed the harness "installs clean on a fresh Windows box and stays wired". Measured on a real one, almost every layer of that was reporting success over work it had not done: a carriage return split the state file the commit gate reads, the installer compared its own `core.hooksPath` against itself and lost, `HOME` pointed at a tree the client never opens, the engram binary the summary reported OK had never been installed or probed, fallow needed a Rust toolchain nothing provisions, the backup announced in phase 1 did not exist until phase 6 and held the run's own work when it did, and the only way to check any of it was a terminal the same page promised you would not need. Every one of those went green. This release closes the class rather than the instances, and states what is actually required instead of "nothing pre-installed":

- **A carriage return no longer splits state, cleanup, and `CLAUDE.md`.** `json_field` captured jq output through `$(...)`, which strips a trailing newline and never a trailing CR, so four gates fed a CR-bearing cwd into the state filename digest — one session wrote `verify_green=true` into one file while the commit gate read another. Both readers strip it now, the pure-bash fallback included, and `state_file_for` strips at the choke point too, where a CR makes `git -C` fail and drops the digest onto a directory nobody named. `gentle-manifest.txt` and `claude-global.md` are LF-pinned and all three manifest readers strip defensively, because `.gitattributes` renormalizes no clone that already exists — with a trailing CR the legacy cleanup removed nothing and `verify.sh` confirmed it as `ok: legacy artifacts removed (0)`. And `merge_global_claude_md` compares its managed-block markers CR-tolerantly, so a re-run stops appending a second copy of a block it could no longer recognize and then blaming the operator for the bloat.
- **Windows paths are compared as keys, and `HOME` is pinned to the tree the client reads.** MSYS rewrites a POSIX path argument before native `git.exe` sees it, so the installer wrote `core.hooksPath` in one spelling and compared it byte-for-byte against another: a second run read its own wiring as a foreign owner and refused, while `verify.sh` told the operator the commit gate was missing with the gate installed. Both sides fold through one normalization now, which is a comparison key and never a stored or printed path. Separately, Git Bash resolves `HOME` from `HOMEDRIVE`+`HOMEPATH` before `USERPROFILE` while `claude.exe` uses `os.homedir()`; on a roaming profile they are different directories, and the installer had been writing `CLAUDE.md`, `settings.json` and every backup into a tree the client never opens — with `verify.sh` reading that same wrong tree and staying green. `install.ps1` pins `HOME` to `%USERPROFILE%` before delegating, and `verify.sh` compares the two for the operator running `install.sh` under Git Bash directly.
- **The Windows prerequisites are decided in PowerShell, and nothing elevates unasked.** `install.ps1` treated every prerequisite as best-effort and then delegated into `install.sh`, whose first act is a hard abort — so a clean machine spent the whole provisioning phase to die inside a bash script with the actionable warning already scrolled away. `Assert-Prerequisites` now runs before delegation and names every unmet requirement at once with the command that closes it, including a Node floor of **22** (what the fallow npm package requires) and a fallback probe for `claude` at its documented native location. `-SkipPrerequisiteCheck` waives the probes for an environment they cannot see — never Git Bash, which the hooks need at runtime and not just to install. Elevation becomes a policy both halves share: user scope first, a machine-wide retry only on the one winget exit code meaning the package ships no per-user installer, only after explicit consent, and never at all under `-Yes`. `install.sh`'s own winget calls had no scope and no guard, so they defaulted to the machine-wide install this forbids and died under `errexit` on a benign non-zero exit; bash cannot read winget's HRESULT through an 8-bit status, so it asks on any per-user failure — asymmetric, and wrong only in the direction of not elevating. `-NoGitHook` closes the flag `install.sh` always accepted and no documented Windows entry point could reach, and CI gains a PowerShell parse step plus a delegation smoke test that records argv with its boundaries marked, so a PS 5.1 splat collapsing four flags into one string goes red instead of reaching an operator as an unknown-flag death.
- **fallow installs from npm, pinned, and counts like every other MCP.** ADR-0066 made fallow the one MCP reported on a `note:` and never counted, because it built from a Rust toolchain nothing here provisions and a hard check would have made the documented one-step Windows path red by construction. That reason is gone: the npm package ships prebuilt binaries for win32-x64, win32-arm64, both macOS arches and linux gnu and musl, so `npm install --global fallow@3.14.0` provisions it on every supported host with Node 22 — which the Windows preflight now requires anyway. Cargo stays documented as an alternative rather than a prerequisite. It is provisioned everywhere, not only on Windows, which is what keeps existing Linux and macOS operators from flipping red the moment the check counts. On Windows the bin is a `.cmd` shim and npm drops an extensionless sh shim beside it that `command -v` finds first and a native client cannot spawn, so the resolver probes the `.cmd` explicitly, asking npm for its own global prefix rather than assuming `%APPDATA%\npm`. And the wiring stops short-circuiting on an entry's mere existence: `claude mcp get` exits 0 for an entry whose command cannot be spawned, so a machine wired by an earlier run to the bare name reported success while the now-mandatory check stayed red and re-running the installer could never clear it. The wired command is read back and compared now, and where it differs the operator is handed the two-step repoint rather than having their user-scope MCP state deleted for them.
- **engram is provisioned, and the summary stops reporting what it never checked.** The installer reported "engram: OK — plugin installed" from a plugin install's exit code while the binary that plugin's `.mcp.json` actually launches was never installed or even probed: a clean Windows box got a green summary and then a bare `FAIL` from `verify.sh`, the one failure in that file carrying no fix string. It is installed now from the pinned release, checksum-verified against `checksums.txt` from the same tag, per-user and without elevation, on Windows and macOS as well as Linux. Presence is never taken for health — the checksum proves which bytes arrived, and running them proves the machine will let them run, so both the placing branch and the already-resolved branch ask the binary to answer; a quarantined copy (upstream documents scanners flagging its unsigned prebuilt releases) surfaces as itself instead of as a PATH diagnosis for a machine whose PATH is fine. The probe reads the PATH Claude Code reads — the persisted machine and user scopes — not this shell's. context7's legacy user-scope entry is no longer deleted before the replacement is confirmed Connected, and impeccable's verdict now comes from the client's own plugin list rather than an install exit code.
- **`oso-state` and Git Bash are published into `settings.json` instead of hoped for on a PATH.** Claude Code injects the plugin's bin into the Bash tool PATH undocumented, and that injection already failed on Windows; when it fails the hook exits clean, so there was no signal at all and every skill fell back to a bare `oso-state` that resolved to nothing — the state layer degraded in silence while the hooks looked like they were running. An absolute `OSO_STATE_BIN` is written into the `env` block from the client's own record of where it installed the plugin, and read back before it is reported. `CLAUDE_CODE_GIT_BASH_PATH` rides along, because all five hooks are `.sh` and a native Windows client without Git Bash loses every gate; `install.ps1` already found that path and hands it over rather than writing it, since PowerShell 5.1's `ConvertTo-Json` defaults to a depth of two and would flatten the nested hook arrays `settings.json` holds. Both writes are jq, on the bash side, after the pre-image that makes them restorable. A value the operator set is never overwritten, one that no longer resolves is repaired, and a stale one on a run handed no candidate is reported rather than guessed at. The desktop app shares `settings.json` with the CLI, so one write covers both surfaces.
- **The backup `install.sh` promises now exists, and holds the state it claims.** `confirm_plan` printed a backup location in phase 1 and the directory was not created until phase 6, so any earlier failure left a path that had been promised and never made. Worse was what it held: `settings.json` is rewritten by three phases before the copy was taken — marketplace add writes `extraKnownMarketplaces`, plugin install writes `enabledPlugins` — so the snapshot held the run's own work rather than what it replaced, and a deliberate `"impeccable@impeccable": false` flipped back to `true` with nothing to restore from. The pre-image is taken in phase 2 now, beside `~/.claude.json` and the plugin registrations, and the later copies are gone so one path means one thing. The coverage report stops claiming registrations it did not hold and names the pre-release `backup-*` snapshots that sit outside this root, and retention reuses `lib/install-backup.sh`'s size bound rather than growing a second one.
- **Windows gets a double-clickable verifier, and CI a report it can read.** README presented `install.bat` as the Windows path with no terminal needed and then offered `bash bootstrap/verify.sh` from a shell as the only way to check the result. `verify.bat` is its sibling: the same Git Bash candidates in the same order, the same pause-only-when-Explorer-launched-it guard, and the same `HOME` pin — without which the new artifact would read a different tree than the client and report green on nothing. `verify.sh` also gains a check for a stored Git Bash path that no longer resolves, and a Claude Desktop line that reports the app on a `note:` either way, present or absent, saying what its presence does not prove — Desktop is an application no installer here provisions, so nothing about it can fail a run and the tally never counts it. CI pins the SET of check names beside the count, since every counted check this release adds fails in a fixture `HOME` by construction and a bare number cannot tell a regression from an absence; `windows-latest` runs `verify.sh` and `verify.bat` for the first time, at Node 22 so it exercises the floor rather than whatever the image carries. The line-ending class is closed rather than patched again: two data files were pinned by name three slices earlier and `plugin/hooks/hooks.json` was the next to reopen it, so one tree-wide `* text=auto eol=lf` replaces every name and extension pin. Nothing was renormalized, every published hash still matches, and three pre-existing Windows failures close on the way past.
