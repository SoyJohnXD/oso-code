# Changelog

The `## Unreleased` section and the three newest releases are kept in full. Every older release is one line; its full text lives in this file's git history (`git log -p -- CHANGELOG.md`), and it says what that release shipped, not what the tree holds now.
From here on a release entry is at most about 12 lines.

## Unreleased

- **OpenCode 2 only.** The OpenCode adapter now loads as a default-exported `{ id, setup }` plugin on the OpenCode 2 plugin contract (ADR 0159): tools register directly under their bare names, plan approval goes through `permission.assert`, the gates run from the `execute.before` tool hook, and idle continuation, system advice and the compaction anchor ride the session hooks. The toast sink and the workspace adapter are gone. The pin moves from 1.18.22 to 2.2.6, `oso install --host opencode` refuses a host below it, and the version probe reads the `opencode v2.2.6` line. Reinstall OpenCode with `node bootstrap/oso.js install --host opencode --yes` and restart it.
- **A load proof in verify.** `oso verify --host opencode` adds the row `installed plugin loads on the host`, which loads the installed bundle on the host under an isolated home and reads the host's own log: a loading line for `oso-code.js` and no `failed to load plugin` line. It skips by name where no `opencode` is on `PATH`.
- **The nightly certifies OpenCode 2.** It drives the six `opencode-v2-*` suites against the pinned 2.2.6 release asset, checksum-verified, and the summary counts their rows.
- **The OpenCode 1 certify suites are deleted.** `opencode-contract-bar`, `opencode-behavior-bar`, `opencode-wave-runner-smoke` and `opencode-prompt-free-posture` bound the retired host and could not run on 2.2.6; they and the support files only they used are gone, and `docs/parity-opencode.md` keeps what they measured as record.
- **The harness speaks OpenCode 2's tool and hook names.** Read-only agents deny `shell` and `subagent` (measured on 2.2.6: the host also still honours `bash` and `task` as aliases of those two), the installer owns `permission.subagent`, and the gate table's OpenCode column names the hooks the plugin registers (`execute.before`, `context`, `compaction`, `experimental.idle`, `cleanup`). The host offers `patch` (input `patchText`) instead of `edit` and `write` for model ids containing `gpt-`, so the edits and unknown gates keep covering `patch`; `todowrite` exists behind the experimental `todo` flag, so every agent keeps its `todowrite` deny; `lsp` was not offered even with every experimental flag on. The rows for `list_mcp_resources` and `read_mcp_resource` are gone because the host hands those tools to hooks as `opencode_list_mcp_resources` and `opencode_read_mcp_resource`. The OpenCode prose guard also refuses `explore`, `synchronous` and `bash` as the shell tool.
- **OpenCode shows only what changed when a plan is re-presented.** When a plan is already held, the first `oso_plan_approve` call with a changed document returns a delta the harness computed from the held snapshot, by section and slice, plus any operational amendments the new document drops; the model relays it and calls again in a later turn, which raises the one approval prompt (ADR 0160). That later turn is opened by a later user message in the session, normally the operator's next one, and a second call from the same turn is refused. The approval stays bound to the digest of the full new document, the previous plan is kept as history, and a re-approval with a slice active is refused. Claude Code is unchanged. The nightly now drives seven `opencode-v2-*` suites.

## 0.29.0

**Release cut: measured-harness rev 4 and proddeploy-false-positives.** This release ships the two measured-harness children (verdict-receipt, loop-cap) and the production-boundary false-positive change. It is based on `5536946` (PRs #64, #65, #69). Reinstall Claude Code with `bash bootstrap/install.sh --yes` and OpenCode with `node bootstrap/oso.js install --host opencode --yes`, then restart each host.

- **Verdict record and receipt.** Every verifier verdict (pass, fail, blocked) is captured on both hosts into `verdicts.jsonl`; a closing `verify_green=true` needs a receipt; `oso-state report` counts slices, rounds and first-fail rates.
- **Capped fix loops.** `/plan` and `/debug` stop at two fix rounds read from `oso-state report`, run an automatic read-only diagnosis at the cap, allow two more rounds, then escalate with a marker; an empty or malformed result counts as a round, never as a verdict.
- **A production boundary that judges what it can read.** The lexer reads up to 32 KiB (ADR 0158), the options of `command`, `xargs`, `env`, `timeout`, `flock` and `taskset`, and numeric `$(( ))` arithmetic, so long PR-body heredocs, `command -v`, `env -u` and `xargs -0` stop being denied. Replayed over the 30-day window ending 2026-09-30, recorded denials fall from 210 to 59.
- **Routes closed on the way.** Deploys behind `timeout 10s`, `flock`, `taskset`, `env -S` (including its own `\_` / `${X}` grammar), `npx -c`/`npm exec -c`/`pnpm dlx -c`/`yarn exec`, `{fd}>` redirections and xargs-fed git, runners and interpreters; pushes with extra refspecs, `--tags`, `GIT_CONFIG_*` or a verb fed by stdin. Lines the lexer still cannot read stay denied.
- **Question rounds for decisions only.** Plan and roadmap deliver intent, maps and findings as chat text; `AskUserQuestion` carries only short decisions.

## 0.28.0

**Release cut: harness-friction.** This release ships the six-child roadmap that cut the friction the harness imposes on both hosts while keeping every quality gate, plus the Windows fix for its liveness watchdog. It is based on `91088ab` (PRs #55–#59, #61, #62). Reinstall Claude Code with `bash bootstrap/install.sh --yes` and OpenCode with `node bootstrap/oso.js install --host opencode --yes`, then restart each host.

- **Friction baseline.** `tools/friction-baseline.ts` measures gate blocks, Stop-net bursts, `oso-state` calls, turns and delegations per mode from Claude transcripts, and from OpenCode's local session database with `--host opencode` (read-only, schema-guarded).
- **Session-scoped state.** `oso-state set` validates keys and echoes what it wrote; the edits, commit and pre-commit gates belong to the session that armed them; a new `oso-state close` disarms a finished flow; every PreToolUse gate runs in one process per tool call.
- **A measured Stop net.** The Claude Stop net tracks in-flight subagents through SubagentStart/SubagentStop and `background_tasks`, holds while they live, counts a commit, a flow transition or a completion as progress (journal writes no longer count), and wakes the run through `oso-state watch` when a subagent is silent 60 minutes, in flight 3 hours or ends unannounced. The model-armed `auto_wait` mark and its 45-minute ceiling are retired. The watchdog is recognized off Linux by liveness and heartbeat where no process start time is readable.
- **Proportional orchestration.** Work under a size threshold (one non-trivial file, or a mechanical edit) is applied inline; larger work goes to the applier; every slice and fix still goes to a fresh verifier.
- **Skill prose per Anthropic's authoring practices.** Scenario evals and phase inventories landed first; every flow names the files it reads one level deep with their conditions; the plan flow's always-read prose fell from 10,972 to 8,000 words; one term per concept.
- **OpenCode friction and parity.** Tool matchers match whole names; unknown tools pass except release-shaped names, unknown tools before a slice is armed, and writes into the installed harness tree; an approved plan is cancelled through a validated transition; compaction re-anchors through `experimental.session.compacting`; a once-per-session drift warning compares the install record `oso-code-install.json` with the running build; the continuation rail holds for running child sessions and releases stuck ones by session id; the installer stops installing and trusting the eight `plugin/hooks/*.sh` gates no host runs and removes the copies earlier installs left. `docs/parity-opencode.md` records each change as parity or gap.

It moved again to 1.18.22 the same way: both bars were driven against `npm pack opencode-linux-x64@1.18.20` and `@1.18.22` binaries and agreed check for check — the contract bar at 67 passed / 0 failed on both, its output identical line for line except the one check whose value IS the pin, and the behavior bar at 11 passed / 0 failed on both, the full battery green on each. The behavior bar's own not-run lane fired on one 1.18.20 run and its re-run closed green at 11, which is the distribution this entry's last paragraph publishes rather than a check answering differently on the two binaries: no check did. 1.18.22 is what an operator installing from https://opencode.ai/install gets today and what `opencode-linux-x64@latest` resolves to, which is the whole reason it is the pin. `SUPPORTED_OPENCODE_VERSION` in `bootstrap/install-opencode.sh` remains the single authority: CI's `npm pack opencode-linux-x64@$pin`, both bars, `bootstrap/verify-opencode.sh` and the suite's own installed-binary comparison read it instead of repeating it, and the three literals `tests/hooks-test.sh` still spelled are derived from it now — three slices running found a stale copy of a number, and fewer copies beats more care. Two decisions taken at 1.18.20 are outside what the two bars reach and were not re-measured for the move: ADR-0155, that a `variant:` with no `model` beside it is dropped when the host reads the agent, and ADR-0156, that a headless child can be auto-refused `external_directory` permission for the worktree it was pinned to.

**The OpenCode host carried the delegation-net defect 0.25.0 fixed on Claude, and carried it worse.** `opencode/plugin/oso/unattended-run.ts` is an independent TypeScript implementation of the same net, writing the same `.waiting` sidecar as `plugin/hooks/auto-continue.sh`, and it keyed a sighting on the journal byte count beside the label and the session. So every turn that journaled a milestone wrote a fresh mark, the mark's age restarted, and the 45-minute ceiling never fired; a hold never touched the push tally, so the three-posted-turn cap never engaged either. Driven over twenty consecutive turns of a run making steady progress under one delegation, this host held twenty times and stopped never, where the bash net on the identical stream holds four times and then pushes. `docs/parity-opencode.md` stated the bound this host did not have, which is what made it a release blocker rather than a defect: shipping it would have sold a bound in writing that nothing enforced.

- **The bounded-renewal design is ported whole, and the two nets are measured agreeing.** The mark is keyed by label and session; progress under a standing mark RENEWS the belief window rather than restarting it unbounded, at most 3 times, so the longest a marked delegation holds is four ceilings and a run that has genuinely stopped moving still meets the first one. Both implementations are driven over the same four streams — a delegation the run keeps moving under, one it has stalled under, an unmarked run, and a mark seconds old, which is the field shape that started this — and answer identically turn for turn on all four. The sidecar they share now carries `renewals` from both sides in the same four records, the same order and the same `0600` mode, and `opencode/plugin/oso/unattended-run.test.ts` drives the bash hook against a mark this host wrote and this host's reader against a mark the bash hook wrote, so the one file two implementations own cannot drift in silence. The bound is written at its true scope where a reader meets it: per `(label, session)`, restarted by a new label, by a `none → label` cycle that removes the mark, and by any external rewrite of it — a bound on one delegation's hold and never a per-run guarantee. One divergence survives the port, and it is robustness under corruption rather than behaviour: a sidecar carrying `renewals` twice — which neither side ever writes, since both rewrite all four records together — reads as 0 in bash, where `state_value` returns both lines and the count test rejects the pair, and as the LAST value in TypeScript, where `parseRecords` is last-wins. So a corrupted mark already at the cap holds on one host and pushes on the other.
- **The linter rule that keeps the suite off the operator's own OpenCode data had three holes and a silent zero.** The awk pre-pass that decides which lines reach the shell lexer skipped every heredoc body, while the lexer behind it distinguishes them — so `bash <<'SH'` / `opencode --version` / `SH` ran unflagged. The whole heredoc goes to the lexer now, which reads a shell-fed body as the commands it is and a `cat` heredoc as the data it is, and the pre-pass no longer decides anything the lexer already decides better. A `case … in` header no longer swallows the invocation sharing its physical line. And a command word that is a variable is matched on the name it actually carries: a name ending in `OPENCODE`, alone or under the suffixes a path to a binary is spelled with — `_BIN`, `_BINARY`, `_EXE`, `_PATH`, `_CMD`, `_CLI`, and compositions of them like `_BIN_PATH` — names the binary, so `$OPENCODE_BIN`, `$OSO_PINNED_OPENCODE_BIN`, `$OPENCODE_EXE` and `$OPENCODE_BIN_PATH` all flag, while `$OPENCODE_CONTRACT_BAR` and `$OPENCODE_INSTALLER` name repository scripts and are left alone. A suite case pins seven of those spellings — `$OPENCODE_EXE`, `$OPENCODE_PATH`, `$OPENCODE_CMD`, `$OPENCODE_CLI` and `$OPENCODE_BIN_PATH` flagging, the two repository scripts not — so narrowing the test back to the one spelling this tree actually carries fails that case rather than passing silently.
- **The silent zero was the expensive one, and it was hiding 95% of the file it was asked about.** awk's stderr went to `/dev/null`, so an unmatched glob would abort it on the missing filename and the rule would report zero sites — a green that never ran. The file list is built in bash against a readability test now, a scan with nothing readable flags instead of passing, and awk's stderr reaches the operator. That guard found its own case on the first run: the pre-pass read `<<PROBE` inside a single-quoted `printf` as a real heredoc opener and, finding no terminator, swallowed every line after line 758 of `tests/hooks-test.sh` — 14,372 of that file's 15,119 lines were never scanned by the rule that reported them clean. Quoted spans are stripped before an opener is looked for, except where the quotes are the delimiter's own, and the scan now reaches that file's last line, whatever it is on the day you read this: 1,057 units where it read 343, at 6.9s of whole-lint wall time where it took 5.3s.
- **The rule's two uncovered forms are stated accurately and pinned by a test.** The first is not the bare `opencode` alone: any `opencode` whose only remaining words are redirects or descriptors goes unflagged — `opencode`, `opencode >/dev/null`, `opencode </dev/null`, `opencode 2>&1` and `opencode >log 2>&1` alike. The second is inherited rather than the rule's own: a logical unit longer than `LEX_MAX_INPUT_BYTES` comes back from the lexer as `!unread-payload` and carries no command word at all, so the same `opencode --version` flags on a short line and passes on a padded one. All six are named in one suite case beside the forms that now DO flag, so the cost is pinned rather than left to be rediscovered, and closing either later fails that case rather than passing silently.
- **Every comment in a shell file this repo ships is gone, and a rule keeps them gone.** The shared rubric has held the inline comment as a debt class with no exceptions since 0.20.0 and this repo was still carrying 3,852 of them, so the retroactive sweep the class always implied finally ran: 3,828 whole-line comments, 4 trimmed off the code they trailed, and 24 inside the awk and python programs that live in a shell string. One block survives per file and only where the file declares no interpreter — a module nothing can run has no other place to state a contract, which is the one thing ADR-0140's own context conceded — so `bootstrap/lib/`'s five sourced libraries plus `plugin/hooks/lib.sh` and `lexer.sh` keep 64 lines across seven files and every other header went with the bodies below it. The bar was not that the suite still passes: `tests/hooks-test.sh`'s full output was captured before and after, `mktemp` paths normalized, and compared byte for byte — 1,785 lines, exactly ONE different, and it is the name of the mutation case that now deletes a table row instead of a header line. Two comments a machine was reading moved rather than died: the linter's rule count is in the line it prints (`lint: clean — twelve rules`), and the four PreToolUse gates' recovery routes are a fourth record kind in `tools/hook-gates.txt`, enforced by the same parser with the same refusal message. `bootstrap/hook-hashes.txt` was re-rendered for the hook bytes that moved, which is the cost this purge was refused for once and accepted for now. `bootstrap/install.bat`, `bootstrap/install.ps1`, `bootstrap/verify.bat` and `bootstrap/lib/toml-regions.awk` keep their 183 comments and are the named remainder: no bar here can run them, and a purge nothing can prove behaviour-neutral is the opposite of the one above.
- **`bootstrap/verify-opencode.sh` stops failing for the host's own permission decision.** It closed `17/1` on three of three clean installs earlier in this change, and that red was never a defect in the tree: the child stream carried `! permission requested: external_directory (…/wt2/*); auto-rejecting` and the write came back `The user rejected permission to use this specific tool call.`, so neither child could create its proof file, while the four isolation assertions the check is NAMED for never fired in any run — nothing was ever violated. Three runs taken when the fix landed closed `18/0` at exit 0 with the smoke completing on `opencode/hy3-free`, so the refusal is real and NOT deterministic: the smoke picks its model out of the host's catalog at runtime, and whether a child's write raises an `external_directory` question at all depends on whether that model writes into the working directory it was pinned to or at the absolute worktree path, which the host measures against a `sandboxes` list naming the project ROOT. Both measurements are in ADR-0156 because one of them alone would be a false claim. The smoke now separates a breach from an incompleteness, reads that one line out of the captured stream, and takes the `not run:` lane it already had — so where the host refuses the report says so by name at exit 3 instead of counting a failure, and where it does not the run is untouched. A child that writes into the OTHER worktree is still red under exactly that refusal, and the suite proves all three outcomes against seeded logs with no host and no model.
- **Nothing guarded the class `.atl/` belonged to, and two rules do now.** No file under this repository may carry the absolute home directory of whoever runs the check — the machine that would leak its own layout is the machine running the linter, which is why the rule needs no username and never fires on the generic `/home/a/b` and `C:/Users/dev/…` examples already in the tree — and no dot-directory may stand beside the repository's own without being either one this repo owns by name or a line in `.gitignore`. The second rule's first finding was `.claude/`, ignored on one machine through a personal global ignore file that no clean checkout and no runner has; it is declared in `.gitignore` now.
- **The close's judges found three fail-opens on this host, and the fourth on the boundary all three share.** `opencode/plugin/oso/gates.ts` re-ran a gate with NO envelope whenever the first run raised `EPIPE`, and returned that blind run's exit as the verdict: three of the four enforcement gates read their whole subject from stdin and exit 0 without one, and the `EPIPE` branch sat AHEAD of the signal guard, so one identical transient gate death came back `block` at a 60-byte command and `allow` at a 2 MB one. A gate that never received its envelope has no verdict now — the signal guard runs first, the blind re-run is gone, and both lengths block. One residual stands beside that fix and nothing in the shim enforces it: a gate that exits 0 without ever reading its stdin raises no `EPIPE` at all where the envelope fits the pipe buffer, and resolves to `allow`. None of the seven can do that today — every one of them reads `$(cat)` unconditionally before it decides anything — but that is a property of how they happen to be written rather than an invariant this host checks, and no test asserts it. `matchesTool` answered `false` for a matcher no regular expression compiles from, which disarmed that route in silence — including the `.*` catch-all that IS this host's default-deny — and a suite case pinned that as intended; a broken matcher is a broken install now, and every route is compiled at load through the same channel a missing gate script reports through, so a table that will not compile denies every tool call. The install-status guard also moved ahead of the matcher test, and that move is not what makes the deny total: reverting the ordering alone, with the load-time compile kept, still denied the call, because the `unknown` gate's `.*` catch-all reaches the install check whatever the tool name is. What the ordering buys is the deny surviving the day that catch-all leaves the table. `opencode/plugin/oso/unattended-run.ts` read a push tally that exists but cannot be parsed as ZERO posted turns so far, where `plugin/hooks/auto-continue.sh` stands the run down on the same file — so one `printf` over the sidecar kept an unattended run posting turns forever, and `PUSHES_WITHOUT_PROGRESS_CAP` never fired. The reading is three-way now — absent, counted, unusable — and both implementations are driven over the same four malformed sidecars, agreeing turn for turn the way slice 22 proved the sighting.
- **At the production boundary an unread payload is production, on every host.** A trailing `# <3 KiB of padding>` puts a line past `LEX_MAX_INPUT_BYTES`, the lexer answers `!unread-payload` and nothing else, and `vercel --prod`, `netlify deploy --prod`, `firebase deploy`, `git push origin main` and `git commit -m x --no-verify` all came back a `residue` both gates ALLOW. `plugin/hooks/lib.sh` gives that marker its own verdict now — `unread`, distinct from the `residue` a lexed-but-unresolvable call earns — and `plugin/hooks/block-prod-deploy.sh` denies it as production, outranking a lexed push in the same line, exactly as its own `arguments_arrived_unread` already failed closed for unread stdin. The cost is stated rather than hidden: while THIS session's unattended run is in flight, any command line past that bound is refused at the production boundary whatever it would have run — `git commit -m x` under 3 KiB of padding is denied there too — and outside an armed run the gate exits before it reads the line at all. The commit rail keeps its polarity deliberately and spends an unread line as residue, because `plugin/git-hooks/pre-commit` stands behind it as a second layer where the production boundary has none — and that second layer is exactly what `--no-verify` skips. `tests/hooks-test.sh` measures shapes against both layers rather than characterizing the gap between them: unpadded `git commit --no-verify -m x`, where the matcher denies and the commit still lands because `--no-verify` is what it names; the same line padded past the lexer's bound, where the matcher allows what it could not read; and `git ci --no-verify -m x` with no padding at all, where the matcher allows because it gates on the git verb and `ci` is not a verb it gates, and the commit lands. That third shape needs no padding to get there because it is the aliased blind spot the same file already pins a few lines above, where the matcher allows `git ci -m x` and the git layer stops it — and `--no-verify` is what takes that layer away.
- **The OpenCode installer placed four executables it never hashed, and its snapshots reached across hosts.** It copied every `plugin/hooks/*.sh` and `chmod 700`d them while the published manifest covered eleven — and one of the four, `plugin/hooks/reanchor-after-compact.sh`, is wired at `opencode/hooks/routes.ts` and executed by the plugin. The manifest's coverage rule now reaches past the Codex-wired handlers to every script the OpenCode route table runs, the installer copies exactly what that manifest names, and a post-install assertion refuses any gate tree holding an executable with no published hash — measured 15 installed against 11 published before, 12 against 12 after. `bootstrap/restore-codex.sh` listed and restored an `install-opencode.sh` snapshot on all three of its paths while its own error string claimed a provenance check it never ran; both installers stamp a format marker and both restores key on their own, the symmetric shape `bootstrap/restore-opencode.sh` already had. Retention enumerated the shared root, so an OpenCode install deleted a Codex snapshot on a budget it never spent, and one shared `.install-restore-verified` file meant exercising either restore armed destructive pruning in both: each host prunes only its own snapshots now and arms on its own marker, so **an operator who exercised a restore before this release must exercise it again on each host before retention resumes there**.
- **Two OpenCode permission blocks granted more than they meant to.** `read: allow` and `bash: allow` are scalars, and this host concatenates the agent block LAST with last-match-wins, so each became a `"*"` rule that erased the installed `read: {"**/.env": "deny"}` and `bash: {"git push *": "ask"}` posture underneath — a thing neither Claude's closed `tools:` allowlist nor Codex's sandbox tier can do. Every scalar grant is gone from `opencode/agents/*.md`: the base and the operator's own rules resolve normally and every deliberate `deny` and the plan agent's narrowed `bash` allowlist stand untouched. And `fallow_fix_apply` — write-capable, in the runtime allowlist, and reachable by four roles documented "judges only — never edits" because no agent declares a `tools:` key — is denied on every non-applier role.
- **A shipped script's sourced library has to be in the INDEX, and the tree bar says so now.** `bootstrap/lib/codex-install-backups.sh` is new in this release, and `bootstrap/install-codex.sh` and `bootstrap/restore-codex.sh` both source it behind a guard that exits when it is absent — so left out of the index it would have handed every clone two scripts that refuse before they do anything, while the machine that wrote them stayed green, which is exactly what a working tree cannot see. `tests/hooks-test.sh` reads every `.sh` path `git ls-files` returns and, on each line that opens with `.` or `source`, takes the literal tail off the last `)` or `$` in it, keeps what holds a `/` and ends in `.sh`, and fails when no tracked path ends in that tail. The index rather than the disk is the whole distinction, and it is proved both ways: on this tree with the file unstaged the rule named both call sites, staged it reads clean, and a fixture repository holding one script and one untracked library it sources takes the rule red and then green as that library is added. Its reach is that cut and nothing wider: `bootstrap/install-codex.sh`'s `. "$SCRIPT_DIR/lib/install-backup.sh"` and `plugin/hooks/lib.sh`'s `. "$(dirname "${BASH_SOURCE[0]}")/lexer.sh"` are in it, while a whole path held in one variable carries no tail to match (`bootstrap/install.sh`'s `. "$BACKUP_LIB"` and `.
